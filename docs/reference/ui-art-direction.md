## 1. 去掉“AI 味”的规则

v0.2 的 demo 看起来像一个调试面板，具体原因和对策：

| v0.2 的问题 | 规则 |
|---|---|
| 侧边栏和按钮栏，每个功能一个按钮 | 操作放在画面里的物件上（点塔位、点水闸、点旗子）；屏幕边上最多一行图标 + 数字 |
| 深色圆角按钮、网页式面板 | 只用像素九宫格面板（第 4 节），而且只在卡片、环形菜单、Esc 菜单里出现 |
| 到处是说明文字和键位说明 | 一屏最多一句引导；键位画成键帽图标放在场景里；说明书式的文字一律不要 |
| 内部单位和编号上屏（cell、斗、A18、297 ms、草案、产材） | 画面上的数字只有：生命、金币、波数，以及买东西的价格 |
| 调试色带、类别边框代替美术 | 水深、沙格这些状态靠美术本身表现（水的深浅、沙的颜色）；调试显示只在开发版 |
| 占位色块（灰底黑通道、红色方块核心） | 每样东西都有精灵或着色器纹理；没有素材时先用本文样稿的画法，不要用纯色块 |
| 各元素大小、风格不统一 | 统一像素网格（1 cell = 1 像素）、统一调色板、统一 1 像素深色描边、统一左上光源 |

## 2. 分辨率、缩放、图层

| | 推箱 | 塔防 |
|---|---|---|
| 基准分辨率 | 320×180 | 640×360 |
| SDK 世界 | 320×192，`cell_scale` 1 | 640×384，`cell_scale` 1 |
| 1 cell | 1 像素；1 格 = 16 像素 | 1 像素 |
| 放大 | ×4（1280×720）、×6（1920×1080）、×8 | ×2（1280×720）、×3（1920×1080）、×4 |
| 参考 | Celeste（320×180） | Noita（模拟像素 = 美术像素） |

- Godot 设置：`display/window/size/viewport_width/height` 填基准分辨率，`stretch/mode = viewport`，`stretch/scale_mode = integer`，所有纹理 `filter = nearest`。窗口不是整数倍时四周留黑边，不做非整数缩放。
- 界面也画在同一个基准分辨率上（和世界一起整数放大），保证像素大小一致。
- 摄像机不动。两作的关卡或地图都在一屏之内。

**图层**（从后到前，两作相同）：

1. 远景：天空、远山（塔防），洞内背景墙（两作）；
2. SDK 世界：自定义着色器（第 5 节），空格透明，露出远景；
3. 背景物件：梯子、目标、塔位框、水车、矿道支架；
4. 角色和活动物件：人物、箱子、敌人、塔、闸门；
5. 特效：粒子、闪光、金币、伤害；
6. 界面。

| 草 | `#265c42` `#3e8948` `#63c74d` |
| 天空（清晨） | `#3a4466` → `#68386c` → `#b55088` → `#f6757a` → `#e8b796` |
| 天空（白天） | `#8b9bb4` → `#c0cbdc` → `#ffffff` |
| 金币、目标、高亮 | `#feae34` `#fee761` |
| 危险、生命 | `#a22633` `#e43b44` |

**字体**：[缝合像素字体 Fusion Pixel Font](https://github.com/TakWolf/fusion-pixel-font) 12px（SIL OFL 1.1，可商用），中英文都用它。文字一律白色或黄色，加 1 像素 `#181425` 描边，不加阴影，不抗锯齿。

## 4. 界面样式

- **HUD**：图标 + 数字，贴着屏幕边，四周不加底板（参考 Kingdom Rush）。图标 7–12 像素。
- **面板**（只用于新东西卡片、环形菜单按钮、Esc 菜单、横幅）：像素九宫格，填充 `#262b44`，外圈 1 像素 `#181425`，上边、左边内侧一条 `#8b9bb4` 亮边，下边内侧一条 `#181425` 暗边，四角各缺一个像素。不用渐变、不用阴影、不用网页式大圆角。
- **按钮**：只有环形菜单的图标按钮（22×22）和 Esc 菜单的文字行。Esc 菜单的“按钮”就是一行字，选中的那行前面画一个黄色小三角，不画按钮框。
- **卡片**：图标 32×32 + 标题一行 + 正文最多两行，宽 160 像素以内，画面正中，点任意处关闭。
- **引导**：手指、键帽、鼠标图标都是精灵（第 7 节）；字放在图标旁边，不加底板，只加描边。
- **悬停 / 可操作提示**：在目标格描 1 像素边（挖用 `#f77622`，倒用 `#fee761`），不填色。
- **禁止**：系统默认控件（Godot 的 Button、OptionButton、ScrollContainer 原样使用）、半透明黑色遮罩盖住整个画面、文字换行超过两行的提示。

## 5. 地形着色器（两作共用的画法）

用 `EleWorld.render_shader_path` 换掉 SDK 自带的调色板着色器。着色器拿到的是每个 cell 的材料 id 和颜色变体（2 位）；在 `vertex()` 里用 `MODEL_MATRIX` 算出世界坐标，就能按世界坐标采样纹理。

| 材料 | 画法 |
|---|---|
| 岩（基岩） | 按世界坐标采样 64×64 可平铺纹理（推箱用 16×16 砌块）；上方是空格的 1–2 行画受光边 `#8b9bb4`、`#5a6988`；与土相邻的边画 1 像素 `#181425`（轮廓清楚，参考 Terraria） |
| 土 | 64×64 可平铺纹理（缓的地层带 + 稀疏碎石）；离空格或水 1 格的画 `#3e2731`，2 格的画 `#733e39`（挖痕，参考 Where's My Water?）；地表线往下 3 行画草 |
| 沙 | 不用纹理，用材料 3 色 + 每 cell 随机变体，看起来就是颗粒；顶面一行 `#ead4aa` |
| 裂岩 | 16×16 纹理带明显裂纹，颜色比基岩暖，一眼能看出“能炸” |
| 水 | 半透明叠在背景上；水面一行 `#2ce8f5`；往上数到水面超过 8 格的画 `#124e89`；不画噪点 |
| 冰 | `#c0cbdc` / `#ffffff` 两色；`ice_thaw` 换 `#8b9bb4` 并加裂纹 |
| 占位材料（推箱的 `crate`、`gate`） | 完全透明，由精灵表现 |

- 纹理要“静”：大块、低对比，噪点只用在沙上。样稿的土和岩噪点太碎，不要照抄。
- 限制：SDK 按 256×256 瓦片画，着色器读不到隔壁瓦片的格，接缝处的挖痕、受光边会断一像素（扩展需求 EXT-10）。demo 接受。
- 洞内背景墙（空格后面）用一张静态图，比岩石暗两级，这样“空间”和“墙”一眼分得开。

## 6. 动效与反馈（两作共用）

| 场合 | 做法 |
|---|---|
| 角色移动 | 格到格 6 帧补间（推箱）；敌人每帧按速度移动，走路动画 8 FPS |
| 落地、碰撞 | 2–4 个灰尘粒子 |
| 进水 | 4 个 `#2ce8f5` 水花粒子 |
| 获得（金币、沙） | 图标弹出 → 沿弧线飞向 HUD → HUD 数字跳一下（放大 1 像素再回来） |
| 受击 | 精灵闪白 1 帧；铁甲兽护甲挡下时闪灰 |
| 爆炸 | 白闪 1 帧、震屏 2 像素 4 帧、碎石粒子（只是画面） |
| 失败、漏怪 | 核心闪红、震屏 1 像素 |
| 过关、守住 | 目标同时亮起 / 横幅，1.5 s |
| 环境 | 挂灯闪烁 2 帧、水面高光偶尔一个像素亮一下、塔防天色按清晨 / 白天 / 黄昏变 |

所有粒子都是游戏层画的，不进 SDK 世界，不影响模拟。

## 8. 检查清单（实现完对照）

1. 截图里数一数界面元素，和两份模板第 2.2 节的清单逐项对照，多一个都不行。
2. 画面上没有 cell、毫秒、编号、调试色带。
3. 只有调色板里的颜色（截图取色检查，半透明混合的水除外）。
4. 所有文字是缝合像素字体 12px，白或黄，带描边。
5. 在 1280×720 和 1920×1080 下截图，像素都是整齐的方块（整数缩放）。
6. 让一个没见过的人看截图 5 秒，问“你觉得该点哪里”，答得出来才算过。
