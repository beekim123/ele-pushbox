# 推箱子：沙与水 · HTML 像素美术与动态生态预演工作台（Art Lab）设计方案

> **设计初衷**：为什么之前直接让 GPT 在 Godot 里写 GDScript 生成美术容易出现“方块 AI 味、缺少灵动细节、UI 拥挤”？因为 GDScript + Headless 测试是“盲写模式”，无法边画边看 60 FPS 动态效果。
> 通过建立一个**零依赖、双击即开的单文件 HTML5 像素美术预演工作台（`tools/art-lab/index.html`）**，我们可以先在浏览器里以极低成本实时打磨**背景、地形 Shader、花草摇曳、森林小动物、天空岛飘云、独特机关像素画以及 UI 页面布局**；等你肉眼确认 100% 满意后，直接点击网页上的**「一键导出 Godot 代码」**，将像素级 1:1 完全相同的代码无损导入真实游戏！

## 1. 核心架构原则：如何保证「HTML 里看到的 == Godot 游戏里跑出来的」？

很多项目先用网页做原型，转到游戏引擎时效果打折，根源在于网页用了 CSS 模糊、矢量贝塞尔曲线、抗锯齿渐变等游戏像素渲染器不支持的特性。为确保 **100% 零损耗 1:1 还原**，本方案采用**「同源原语 + 逐像素软件着色器」**架构：

| 渲染层级 | HTML 预演工作台（`index.html`）实现方式 | Godot 真实游戏（`pushbox/`）对应落点 | 1:1 无损对齐机制 |
| :--- | :--- | :--- | :--- |
| **1. 逻辑画布与缩放** | `<canvas width="320" height="180">` + CSS `image-rendering: pixelated;`，支持 `×2 / ×4 / ×6` 整数倍放大检视 | `320×180` 基准分辨率 + `stretch/scale_mode = integer` + `FILTER_NEAREST` | 物理像素网格完全锁定为 `320×180`（1 格 = `16×16` 像素），禁止任何亚像素浮点绘制或抗锯齿 |
| **2. 调色板约束** | JS 常量锁定 `ENDESGA_32`（`a..z, A..F` 共 32 色），网页取色器仅允许点选这 32 色 | [`pushbox/scripts/art/palette.gd`](../pushbox/scripts/art/palette.gd) | 颜色编码字符（`a..F` 与 `.` 透明）双端 100% 通用 |
| **3. 底层绘图原语** | JS 版 `CanvasOps`：操作 `ImageData (Uint8ClampedArray)`，仅提供 `rect()`、`line()`（整数 Bresenham）、`dither_rect()`（2×2 Bayer 抖动）、`h32(x,y,seed)`（32 位整数哈希） | [`pushbox/scripts/art/canvas_ops.gd`](../pushbox/scripts/art/canvas_ops.gd) | 数学公式与位运算（`& 0xFFFFFFFF`）完全一致，同一个坐标 `(x, y)` 算出的随机哈希在网页与 Godot 中分毫不差 |
| **4. 地形着色器模拟** | JS 逐像素运行 `simulateWorldShader(px, wp, tile_pixel, biome_style_id)`，计算基岩砖缝、3px 森林草皮、天空岛 3px 底面云絮、宇宙黄黑斜纹、水深与酸/熔岩纹理 | [`pushbox/scripts/render/world.gdshader`](../pushbox/scripts/render/world.gdshader) | 将 GLSL 的 `fragment()` 逻辑用 1:1 等价的 JS 函数在 `320×180` 像素缓冲上实时运行 |
| **5. 精灵与小动物矩阵** | 统一使用 `String[]` 字符矩阵数组（如 `forest_bird_0..3`、`flower_sway_0..1`）驱动帧动画 | `pushbox/scripts/art/sprites/**/*.gd` | 网页上修改任何一个像素格，底层直接修改该字符矩阵，一键复制即为合法 GDScript 字典 |
| **6. 动态生态与飘云** | `requestAnimationFrame` 驱动 `clock` 变量（8 FPS 精灵帧 + 视差整数位移 `Math.floor(clock * speed)`） | `board_view.gd` / `ambient_ecology.gd` 的 `_process(delta)` 与 `_draw()` | 运动轨迹公式（如蝴蝶正弦轨迹、三层云朵视差速度 `2 / 5 / 10 px/s`）双端共用同一套参数表 |

### 视图 1：六大风格全场景动态实验室（Scene & Ecology Preview）
- **功能定位**：专门解决“地图没特点、背景死板、花草小动物和飘云看不见效果”的问题。
- **交互能力**：
  1. **一键切换 6 大风格地图**：点击顶部标签秒切 **幽暗石牢 / 迷雾古森 / 黄金神庙 / 幽光晶窟 / 云端圣域 / 深空星站**。
  2. **动态生态实时开关与调参**：
     - 在**森林风格**下：实时看到草皮上的红/黄/蓝三色小花随风摆动、红胸知更鸟/翠鸟在平台边低头啄草与蹦跳、彩蝶在花丛上飞舞、古树光束与落叶飘落；如果不满意某只小鸟的颜色或动作节奏，当场拖动滑块或点选色卡就能看效果。
     - 在**天空岛风格**下：实时看到破晓 `2×2` Bayer 抖动天幕、远/中/近三层蓬松白云以不同速度平滑飘过画面、4 帧旋转的小风车、悬空岛底部的 3px 白云包边与浮云软垫呼吸起伏。
     - 在**遗迹 / 洞穴 / 宇宙 / 地牢**下：实时预览顶棚细金沙漏流与黄金圣甲虫、钟乳石滴酸溅花与水晶飞蛾、深空旋转小行星与巡检微型无人机、石牢眨眼小蝙蝠。
  3. **地图地形直接涂刷（ASCII Map Live Painter）**：鼠标可直接在画面上涂刷 `#`（基岩）、`c`（裂岩）、`s`（沙）、`w`（水）、`a`（酸）、`m`（熔岩）、`i`（冰）以及摆放木箱、铁箱和独特机关，当场实验“拱形树洞”、“无边框纯浮岛”、“金字塔阶梯”等去火柴盒化地形！

### 视图 2：小动物 / 植物 / 独特机关像素画板（Sprite & Anim Inspector）
- **功能定位**：专门解决“单个精灵或机关画得粗糙、有 AI 味、多格机关缩放变形”的问题。
- **交互能力**：
  - 左侧列出全游戏所有精灵与新增生态资产（如 `forest_bird_0..3`、`butterfly_0..1`、`flower_sway_0..1`、`cloud_far/mid/near`、`vine_ladder_0`、`sand_funnel_0`、`golden_scale_0`、`mini_drone_0..1` 等）。
  - 中央提供 **`16×16` / `8×8` / `32×32` 放大网格画板**，右侧同时播放 `1×`、`4×`、`8×` 的 8 FPS 循环动画预览。
  - 你可以直接用鼠标在网格上点选 ENDESGA 32 色块修改小动物的眼睛、翅膀或花瓣形状，改完瞬间反映到“视图 1”的大地图场景里！

### 视图 3：UI 页面美化预演器（Lobby / 闯关地图池 / 观察池 UI Previewer）
- **功能定位**：专门解决“UI 页面太不美观、文字挤爆边框、比例不协调”的问题。
- **交互能力**：
  - 在 `320×180` 标准画布上完整渲染重构后的 **3 张核心 UI 页面**：
    1. **主大厅（Lobby Modes）**：动态主题背景 + 三大模式精修九宫格卡片；
    2. **闯关模式 · 六大地图航线与关卡池页（Campaign Pool）**：顶部 6 大地图图标航线条 + 左侧带藤蔓/金纹/白云装饰框的实景动态微缩窗 + 右侧 `2×3` 纯图标清爽关卡卡槽（星标 `★`、金冠、银灯笼）；
    3. **观察池（Observation Pool）**：无大黑条的 `320×180` 通透全景侦察界面。
  - 支持直接在网页上用鼠标悬停、点击切换地图标签和关卡卡片，提前检验间距、字号、配色与动效过渡是否足够精致美观。

### 视图 4：Godot 代码一键导出器（1:1 Code Generator & Exporter）
- **功能定位**：打通**「HTML 预演确认 → 100% 原样导入真实游戏」**的最后一公里。
- **导出产物（点击按钮直接生成可复制/下载的 `.gd` 代码块）**：
  1. **导出精灵与小动物矩阵（`ambient_ecology_art.gd` / `biome_gimmicks_art.gd`）**：自动把网页中微调好的字符像素矩阵打包成符合 Godot 规范的 `const PIXELS := { ... }` 脚本。
  2. **导出主题背景与生态配置（`theme_<name>.gd` & `ambient_ecology.gd`）**：将调好的抖动天幕、古树视差参数、飘云速度、花鸟生成规则直接输出为 GDScript 函数。
  3. **导出重设计后的地图 JSON（`showcase/*.json` & `campaign/*.json`）**：将在网页画布上涂刷定稿的去火柴盒化地图布局直接输出为标准关卡 JSON。

## 3. 工作流革新：以后的标准美术与界面迭代流程

有了这个 HTML 预演工作台后，后续无论是调整现有 6 大地图，还是未来第三阶段增加“深渊熔炉”、“机械齿轮城”或“塔防敌人/防御塔”，都遵循以下**三步零返工流程**：

1. **第一步（HTML 快速打样与肉眼把关）**：
   先在 `tools/art-lab/index.html` 中写出新精灵、新地图生态动效或新 UI 布局；你直接双击网页打开看实时动态效果，哪里有 AI 味、哪朵花不够灵动、哪个 UI 间距不好看，我们在网页里秒改秒看（不需要等 Godot 跑几十秒自动化测试）。
2. **第二步（一键导出同源规格与 GDScript 代码）**：
   网页效果让你 100% 满意后，直接从网页的「导出面板」生成对应的 GDScript 像素矩阵、绘制函数与坐标参数。
3. **第三步（交由 GPT 无损合入 Godot 并跑测试）**：
   让 GPT 直接把网页导出的现成代码贴进 `pushbox/scripts/art/` 与 `pushbox/scripts/ui/`（禁止 GPT 自己自由发挥乱画矩形），只负责接好逻辑信号并跑通 `run_tests.py` 即可！
