# 推箱子：沙与水 · 游戏设计（唯一有效版本）

版本：GD-2，2026-10-15。本文件取代仓库此前全部玩法、关卡和阶段规划文档（旧文档保存在快照 `0fae58c`，不再作为执行依据）。修改玩法时只改本文件，并在文末更新记录中写明。审核过程和取舍理由见 [设计审核记录](../audit/2026-10-15-design-audit.md)；SDK 事实见 [SDK v1.2 核实记录](../reference/sdk-v1.2-verified.md)。

文中三类陈述分开标注：

- **【SDK】** 由 ele-base-cpp v1.2.0（`dacb93e`）的物理求解器完成，已在源码中核实接口存在。具体手感和数值仍需在样板中实测。
- **【游戏层】** 由游戏代码按确定规则执行，例如推箱、压板、门、背包。
- **【待验证】** 设计依据充分，但必须先做样板验证，才能用于正式关卡。

## 1 产品定位

全程横版、侧视、按格移动的推箱解谜。玩家推箱、攀爬、挖土、倒沙、放炸药；沙、水、气体、火和冰由 SDK 真实模拟。主要乐趣是"我知道这个东西会怎样了，于是可以这样用它"。

体验目标：

1. **先看懂，再尝试**。每关开局就能看见目标、可操作物和关键关系，不靠隐藏规则。
2. **试错零成本**。撤销即时可用、无次数限制，重开无确认；失败不扣资源、不计评价。
3. **思考多于执行**。主线没有跳跃、精确时序、长途往返或重复搬运。
4. **物理是因果，不是随机**。动作提交后播放变化，播放结束后再操作；同样的操作永远得到同样的结果。

明确不做（本版本）：俯视章节、跳跃与空中操控、实时敌人、倒计时、多角色同时操作、星级评分与步数排行榜、挑战 / 地狱模式。挑战模式保留为远期方向，不进入当前规划。

## 2 核心循环与操作

循环：观察房间 → 选择一个动作 → 观看结算 → 判断结果 →（撤销或继续）→ 点亮全部目标灯 → 过关。

| 动作 | 键盘 | 鼠标 | 规则摘要 |
|---|---|---|---|
| 走 / 推 / 登阶 | ←→ 或 A D | — | 见 4.2 |
| 爬梯 | ↑↓ 或 W S | — | 只在梯子格内上下 |
| 挖 | 按住 Shift + 方向（左、右、下） | 左键点相邻格 | 挖夯土或散沙，背包 +1 袋 |
| 倒沙 | 按住 Ctrl + 方向（左、右） | 右键点相邻格 | 背包 −1 袋，在目标格生成一格沙 |
| 放炸药（第 3 章起） | B + 方向（左、右、下） | 把炸药图标拖到相邻格 | 见 4.6 |
| 撤销 | Z（可按住连撤） | HUD 撤销按钮 | 无次数上限（存储上限 200 步，超出时丢弃最早的） |
| 重开 | R | HUD 重开按钮 | 无确认，可再撤销回重开前 |
| 观察 | Tab（按住） | HUD 眼睛按钮 | 见 7.4 |
| 提示 | H | HUD 灯泡按钮 | 见 7.2 |
| 暂停菜单 | Esc | — | 继续、提示、重开、选关、设置、返回大厅 |

键盘修饰键方案取代 v0.3 只能用鼠标挖、倒的做法，让纯键盘也能完成全部操作。鼠标点击只对相邻且合法的格生效；悬停时显示目标高亮（7.4）。结算播放中按任意键快进到结算结束，不排队后续输入。

## 3 世界、格子与结算

### 3.1 尺寸

- 逻辑画面 320×180，整数放大（1280×720 为 4 倍，1920×1080 为 6 倍）。非整数倍的窗口留边，不做非整数缩放。
- 1 格 = 16×16 像素 = 16×16 个 SDK cell（`cell_scale = 1`）。
- SDK 世界 320×192（宽和高必须是 64 的倍数【SDK】）。关卡最大 20×10 格，放在 20px 高的 HUD 条下方并居中。
- 关卡房间外圈全是基岩。

### 3.2 两层表示

- **SDK 世界**保存所有材料 cell，负责落沙、流水、反应、燃烧、爆炸等物理。
- **游戏层**保存人物、箱子、背包、门、压板、目标、装置等状态。人物不写进 SDK；箱子同时以 16×16 个 `crate` / `iron_crate` static cell 写进 SDK，让流体和沙能被它挡住。
- **格子分类**：每次结算结束后读取全图材料，按每格 256 个 cell 中占多数（≥128）的类别归类为 SOLID、EARTH、SAND、WATER、EMPTY 等，供移动规则使用（沿用 v0.3 的阈值做法）。

### 3.3 回合结算【SDK + 游戏层】

1. 玩家动作合法 → 保存撤销点 → 游戏层更新实体，并提交对应 SDK 命令。
2. 逐 tick `step(1)` 推进，动画按每帧 4 tick 播放（快进时每帧不限 tick、单帧耗时有预算）。
3. 判定静止：连续 4 tick 满足 `active_chunks == 0`、`queue_size == 0`、`pressure_moves == 0`；启用电路时还要 `electric_heads == 0`。
4. **温度变化不会体现在 Godot 侧的统计里**【SDK，已核实】。凡是依赖温度的装置（点火、加热），都按装置定义的固定阶段长度推进，阶段结束后再判静止。
5. 静止后重新分类格子，游戏层依次执行：箱子与人物的重力、木箱浮起、压板与门；如有变化，回到第 2 步。
6. 单次结算上限 1200 tick 或 16 轮。触顶记为异常：开发版报错，正式版回滚到动作前。关卡设计不得触顶。

### 3.4 搬运不保留状态【SDK，已核实】

推箱、挖土、倒沙、开关门都是"清除旧格 + 写入新格"。新写入的格会重新生成随机颜色位和寿命，燃烧状态清零；温度不会随材料移动，只在新材料定义了 `spawn_temp` 时写入。因此：

- 正在燃烧、带寿命计时、温度异常的材料不能被挖取，也不能被推入或倒入。游戏层先检查这些状态再允许动作。
- 箱子材料不可燃，`blast_resistance = 65535`。

## 4 规则（格子级）

本节规则由 `workbench/js/core/tilemodel.js` 实现为设计模型，供关卡检查与工作台预演使用。模型不模拟 SDK 物理；涉及流体、气体、火、冰的关卡，模型只做辅助检查。

### 4.1 支撑与下落

- 能支撑的格：岩石、裂岩、夯土、沙、关闭的门、箱子。
- 人物所在格的下方不能支撑、自身又不在梯子格内时，人物逐格下落，没有摔落伤害。
- 箱子下方空了就下落；箱子可以叠放，可以压在人物头上（人物离开后再落）。
- 散沙由 SDK 落下和堆积。夯土是 static，挖掉下方的夯土，上方的夯土不会掉落。

### 4.2 水平移动

按优先级依次判断：

1. 前方是箱子，且箱子另一侧可进入：推动箱子一格，人物跟进。每次只推一个箱子，不推箱子链。
2. 前方可进入：走过去，然后执行下落。
3. 前方是能支撑的格，而人物头顶和前方那格的上方都空：**登上一格**。两格高的障碍登不上。
4. 以上都不满足：被挡。播放受阻反馈，不计步数。

"可进入"指空格、水格或背景标记格（梯子、目标槽、压板、出口），且其中没有箱子或人物。

### 4.3 梯子

人物在梯子格内不会下落。↑ 只能进入上方的梯子格；↓ 可以离开梯子向下走。在梯子格内左右移动遵守 4.2。梯子不支撑箱子。

### 4.4 挖取与背包

- 只能挖左、右、下三个相邻方向的夯土或沙。每挖一格背包 +1 袋，背包上限 9 袋。
- 背包只计"袋数"。1 袋 = 1 格 = 256 个 sand cell。
- 夯土【游戏层规则 + SDK static 材料】：褐色带碎石，不会坍塌，是主线中可挖墙体的主要材料。挖出来的同样是 1 袋沙。

### 4.5 倒沙

- 只能倒在左、右相邻、可进入且没有实体的格，每次倒 1 袋。SDK 中写入 256 个 sand cell，由求解器落下、堆积，沉入水中时把水挤上去。
- **设计约束**：主线中需要成为整格的倒沙，落点必须靠墙或落进坑里。空旷平地上的一格沙会摊成小坡，按阈值仍可能判为一格，但不作为解题关键。【待验证：靠墙一格沙的溢出量必须少于 128 cell。】

### 4.6 炸药（第 3 章起）

- 只能放在左、右、下三个相邻格。模型中会清除目标格及其上下左右四格内的裂岩、夯土和沙；基岩、箱子、门不受影响。
- SDK 中执行 `explode(格中心, 20, 8000)`。爆炸**没有遮挡**【SDK，已核实】：墙后面的格也会受影响，只按距离和抗爆性判断。剩余不足一半的裂岩格整格崩落（v0.3 做法）。
- 人物不受伤害。

### 4.7 压板与门【游戏层】

- 压板格被人物、箱子或任何实心材料压住时视为按下。同一关所有同符号的压板都按下，对应的门才打开。
- 门打开时清除门格材料；关闭时写回。门格内有人物或箱子时，门保持打开直到让开，不挤压、不吞物。
- 门和压板用同一形状符号配对（圆、三角、方块），不只靠颜色区分。第 1 章每关最多一组。
- 锁存门（离开后仍保持打开，并亮锁存灯）留到第 2 章以后，并且必须单独教学。

### 4.8 目标与过关

- 每关有一个或多个**目标灯**。所有目标灯同时点亮，即在该次结算结束时过关。
- 目标类型：箱子槽（槽内有箱子）、出口旗（人物站在旗上）、收集斗（斗内材料达到刻度，并锁存保持点亮，第 2 章起）。
- HUD 显示"已点亮 / 总数"。过关时播放约 1.2 秒的庆祝动画，按任意键可以跳过。

## 6 章节与关卡

### 6.1 结构

主线共 5 章、33 关。每章就是一个视觉主题：

| 章 | 主题 | 核心机制 | 主线关数 | SDK profile |
|---|---|---|---|---|
| 1 矿道 | 暖色木支架、矿灯 | 推、梯、挖、倒、压板门 | 7 | cells |
| 2 水渠 | 青石拱渠、流水 | 水流、浮箱 / 沉箱、挤水、连通器、升降台 | 7 | cells、liquid_pressure |
| 3 采石场 | 赭红岩壁、天光 | 炸药、裂岩 / 基岩、隔墙爆破、引信连锁、慢碎石 | 6 | cells、thermal、explosions |
| 4 苔林 | 绿苔、紫影、萤火 | 酸蚀标签、上浮 / 下沉气体、寿命塞、藤梯 | 7 | cells（反应、气体、寿命都由 cells 执行；藤梯是游戏层） |
| 5 熔窟 | 玄武岩、熔光、冰青 | 点火烧栅、冷凝成冰、热喷化冰、炸药引燃 | 6 | cells、thermal、explosions、couplers |

每章的结构：前两关教学，中间巩固或变化一个条件，最后 1–2 关是轻组合（最多两个关键决定）。关卡数量服从教学需要；不足以单独成关的变化并入其他关，不为凑数加关。

### 6.2 解锁与选关

- 第 1 章开局全部开放。在上一章通关"主线关数 − 2"关（第 1、2、4 章为 5 关，第 3、5 章为 4 关）即可解锁下一章。
- 已解锁章节内的关卡可以任意选择，界面给出推荐顺序。
- 设置中的"开放全部关卡"用于试玩和开发，打开后不伪造通关记录。
- 跳关进入的房间若用到玩家没学过的概念，开局在 HUD 旁显示该概念的**规则卡**（图标 + 两帧动画 + 一句话），可随时点开。

## 7 系统

### 7.1 撤销与重开

- 每个合法动作前保存撤销点：SDK `save_snapshot` 写入 `user://undo/`，同时保存游戏层状态 JSON（实体、背包、门、目标锁存、装置）。上限 200 步。
- 撤销恢复快照和游戏层状态，不重放；重开读取开局快照。重开本身也算一个撤销点。
- 关卡退出时清理快照目录。
- 扩展章若使用刚体：带刚体的快照读回后不保证位级一致【SDK，已核实】，只能改为"从无刚体的开局重放全部命令"实现撤销，届时单独设计。

### 7.2 提示

1. 第一层：高亮相关对象（关卡数据 `hints[0]` 的文字，加上对象描边）。
2. 第二层：说明因果关系（`hints[1]`）。
3. 第三层：说明下一步怎么做（`hints[2]`），并提供"演示"按钮。演示从当前状态播放作者解的剩余步骤；当前状态不在作者路线上时，按钮改为"回到最近的正确位置"——从撤销历史中找出最近一个与作者路线某步一致的状态并撤销过去；找不到时提示重开。
- 状态一致性只比较游戏层局面（人物、箱子、格子分类、背包），不比较 SDK 哈希（哈希包含 tick 数，不适合用来比较）。
- 使用提示不影响通关、解锁和任何记录。

### 7.3 跳关

关卡选择界面允许直接进入任何已解锁的关卡。暂停菜单提供"跳过此关"：标记为已跳过（不算通关），回到关卡选择。规则卡机制见 6.2。

### 7.4 观察与目标高亮

- **观察**（按住 Tab）：显示格子网格、格子分类小图标、压板与门的配对连线、目标灯列表；画面变暗 30%，人物不可操作。
- **目标高亮**（悬停或按住修饰键时）：只显示按规则确定的结果，不运行模拟。包括挖取目标格、倒沙落点所在的整列、炸药的十字影响区（标出会崩落的格）、推箱后的箱子落点。
- **取消 v0.3 的整局预演模拟**：它需要第二个 SDK 世界和分帧调度，复杂度高；撤销已经免费，因此不再保留。

### 7.5 存档

`user://progress.json`，带 `version` 字段：

```json
{"version":1,"levels":{"M01":{"cleared":true,"skipped":false,"best_steps":4}},
 "chapters_unlocked":["mine"],"rule_cards_seen":["push"],
 "settings":{"open_all_levels":false,"show_grid":false,"music":0.8,"sfx":0.8,"window_scale":"auto"}}
```

写入采用"先写临时文件，再改名"。读取失败时备份损坏文件并重建。

### 7.6 引导

教学关的动作提示做对一次后就消失，并记录在 `rule_cards_seen` 中；设置里提供"重看引导"。键位提示使用按键图标（见美术清单 `ui.key.*`）。

## 9 扩展章候选（不在当前范围）

以下内容等主线 5 章完成并经过试玩后再决定，每项都要先通过技术样板：
