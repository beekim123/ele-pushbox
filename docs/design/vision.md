## 1 一句话

你是一名配送员，什么都送：一封信、一支冰淇淋、一架钢琴。推箱、攀爬、挖土、倒沙、放炸药，利用会流动、会燃烧、会结冰的真实材料（由 ele-base-cpp SDK 模拟），把东西送到收件人手里。

## 2 三个模式

| | 关卡模式 | 配送模式 | 地狱模式 |
|---|---|---|---|
| 一句话 | 每关只演示一个机制，也是新机制的试验场 | 每局随机一件货物，货物自带规则；穿过多个房间，避开或放倒怪物，送到收件人手里 | 纯推箱解谜，难度高，不给提示，自己探索 |
| 地图 | 一屏一个小房间 | 多个一屏房间拼成的大地图 | 一屏一个房间，按"层"开放 |
| 难度 | 低（教学） | 中 | 高 |
| 随机性 | 无 | 有（货物、地图、怪物） | 无 |
| 有没有标准解 | 有作者解，提供三级提示 | 主路径保证可通，解法自由 | 不公开解法，允许多解；但每关上线前必须验证至少有一个解 |
| 局外养成 | 不受影响 | 受影响 | 只发奖励，难度不受影响 |
| 什么时候做 | **现在**：重构游戏并把现有机制全部做进来 | 关卡模式完成之后 | 建议在关卡模式之后、配送模式之前（待你确认） |

## 3 关卡模式是地基

三个模式共用同一套格子规则、SDK 材料、机关、角色动作和美术。规定：**任何机制先在关卡模式里做成一关并验证通过，才能用到配送模式和地狱模式**。

以后给 SDK 加新机制（例如电、气压、粒子），流程是：在机制目录登记 → 在关卡模式的"实验组"做一个最小关卡 → 在 Godot 中用真实 SDK 自动验证 → 美术确认 → 正式开放。关卡模式因此同时是 SDK 的回归测试：每关的验收条目都要能自动运行（详见 [game-design.md](game-design.md) 第 6 节）。

## 4 主角与世界

- **主角**是一家"什么都送"的配送公司的配送员。公司的业务遍布六个地区，正好对应已确认的六个主题：幽暗石牢、黄金神庙、幽光晶窟、迷雾古森、云端圣域、深空星站。关卡模式里，地区就是机制组的场景；配送模式里，地区就是送货的区域。
- **主角形象**：已确认的 `char.miner` 是戴安全帽、拿铲子的矿工。新设定建议改画成配送员（帽子、制服、斜挎包，铲子换成折叠铲），保留现有 21 帧的全部动作。改画会产生新版本，需要你确认。**待你决定是否改画、何时改画**；在你决定之前，现有矿工形象照常使用。
- **界面用词**（随改名一起改，改动 `content/i18n` 会让界面布局生成新版本，需要重新确认）：箱子槽可称"投递点"，过关可称"送达"。关卡模式的玩法和规则不变。

## 7 和 GD-2 的关系

- GD-2 的格子规则、系统、界面、第 1 章 7 关、第 2–5 章概念卡全部保留，归入关卡模式。原来的"章"改称"机制组"，主题不变。
- 第 2–5 章概念卡中的"组合关"（W06、Q05、Q06、G07、F05、F06）不放进关卡模式，移入地狱模式的候选池。关卡模式只保留"一关一个机制"。
- GD-2 第 1 节"明确不做"的内容（倒计时、实时敌人、星级、挑战模式等）仍然适用于关卡模式。配送模式和地狱模式各自的规则写在各自的文档里。
- 已确认的美术全部继续有效（`APR-0001`、`APR-0002`）。
