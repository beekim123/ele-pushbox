# 对话系统与气泡（设计稿，第一步已实现在工作台）

状态：2026-10-15 用户要求"提示文案用角色的气泡框包裹，字体小一点；以后做成对话系统（感叹号接任务、NPC 自言自语、配送送达后的隐藏对话等）"。第一步（气泡外观 + 关卡提示改用气泡）已画进工作台，等用户确认；对话数据和触发器是后续内容，这里先把结构定好，开发时一次做对。

## 1 原则

1. **角色说的话都进气泡**：关卡提示、主角自言自语、渡口居民、收件人、怪物的叫声。菜单、标题、按钮、HUD 不是"说话"，仍用 12px 面板。
2. **气泡字用 10px 小字**（Fusion Pixel 10px，`third_party/fonts/fusion-pixel-10px/`），行高 12px；菜单仍用 12px。
3. **气泡贴着说话人**：尾巴指向说话人头顶；上方放不下就放到下方，尾巴翻转；永远在屏幕内（左右各留 3px）。
4. **不挡操作**：普通气泡只是显示，玩家照样能走；只有"对话"（要按键翻页、要做选择）才暂停输入。
5. **所有文字来自语言表**：键名 `dlg.<对话编号>.<句号>`；关卡提示仍是 `level.<编号>.hint.<n>`。

## 2 气泡样式（美术：`ui.bubble`、`ui.bubble_tail`、`ui.emote`）

| 样式 | 用途 | 外观 |
|---|---|---|
| `say` 说话 | NPC 交委托、收件人道谢、提示 | 米色底、深色字、圆角、尖尾巴 |
| `think` 心里话 | 主角自言自语、NPC 闲聊、怪物嘀咕 | 浅灰蓝底、小圆点尾巴 |
| `sign` 告示 | 系统说明、新委托、告示牌 | 木色方角、无尾巴 |

- 气泡宽度按文字伸缩，最大 150px（提示 168px），最多 4 行，超出报告溢出（和界面同一套检查）。
- 名牌：说话人名字画在气泡左上角的小木牌上（12px）；提示的名牌写"提示 n/3"。
- 逐字显示：每秒 30 字；按任意键立即显示全句，再按翻到下一句。设置里可以关掉逐字显示。
- 头顶标记 `ui.emote`（上下浮动 1px）：`!` 有委托可接、`?` 委托进行中、`…` 在自言自语（靠近会冒气泡）、`♥` 好感提升、`✓` 委托完成。

实现：`workbench/js/core/dialogue.js`（排版、气泡、标记）、`font-small.js`（10px 字形）。工作台「场景」页：`ui.screen.hint`（关卡提示）、`ui.screen.dialogue`（样张：渡口居民交委托、主角心里话、新委托告示）。

## 3 数据（以后的版本）

对话存在 `content/dialogue/<分组>/<编号>.json`，格式 `pushbox.dialogue/1`：

```json
{
  "format": "pushbox.dialogue/1",
  "id": "hub.old_miner.ore_delivery",
  "speaker": "npc.old_miner",
  "trigger": {"type": "talk", "where": "hub"},
  "when": {"license_level": ">=1", "flag_not": "ore_delivered"},
  "emote": "quest",
  "lines": [
    {"key": "dlg.hub.old_miner.ore_delivery.1", "style": "say"},
    {"key": "dlg.hub.old_miner.ore_delivery.2", "style": "say", "choices": [
      {"key": "dlg.common.accept", "do": [{"start_quest": "quest.ore_to_temple"}]},
      {"key": "dlg.common.later"}
    ]}
  ]
}
```

- `speaker`：说话人的内容编号（主角 `char.portitor`、居民 `npc.*`、收件人 `recipient.*`、怪物 `monster.*`），气泡锚在它头顶。
- `trigger`：什么时候冒出来。

| 类型 | 例子 |
|---|---|
| `talk` | 走到 NPC 旁边按 ↑ |
| `near` | 靠近到 N 格内（自言自语） |
| `level_start` / `level_idle` | 关卡开局；站着不动 N 秒（主角自言自语提示） |
| `hint` | 按 H（现在的三级提示） |
| `deliver` | 配送模式送达时（收件人的话；`when` 可以要求评级、缘分组合、好感，做"隐藏对话"） |
| `event` | 配送模式随机事件 |
| `flag` | 某个剧情标记被设置时 |

- `when`：条件（执照等级、好感、标记、已完成的委托、货物 × 收件人组合）。
- `do`：效果（开始 / 完成委托、设置标记、加好感、给物品），由对应的系统执行（[architecture.md](architecture.md) 的事件总线）。
- 同一个说话人同时满足多条对话时，按 `priority`，再按"没看过的优先"。
- 看过的对话记进存档（`dialogue_seen`），隐藏对话只出现一次。

## 4 分步上线

| 步 | 内容 | 用在哪里 |
|---|---|---|
| 1（现在） | 气泡外观、10px 小字、关卡提示改成主角说话 | 关卡模式 |
| 2 | 对话数据格式、`talk` / `near` / `level_idle` 触发、头顶标记 | 渡口（大厅）居民、关卡里主角自言自语 |
| 3 | 委托系统（接任务 `!`、进行中 `?`、完成 `✓`）、选项 | 渡口委托 → 配送模式 |
| 4 | `deliver` / `event` 触发、隐藏对话、好感 | 配送模式 |

工作台以后加「对话」页：按说话人列出全部对话、条件和效果，能在场景里预览气泡；内容检查要核对说话人、键名、条件里用到的编号都存在。
