## 1 房间与口位

- 一个房间 20 × 10 格（320 × 160 像素，放在 20 像素高的 HUD 条下面），和关卡模式的关卡一样大。外圈是基岩，只有出入口是开着的。
- **口位**是出入口在边上的固定位置。相邻两个房间共用的那条边，两边开的口位必须相同，否则对不上。

| 边 | 口位 | 开口 | 必须满足 |
|---|---|---|---|
| 左、右 | `low` | 第 6、7 行（人站在第 7 行） | 开口两格是空的；脚下第 8 行、头顶第 5 行是基岩；里面一格空着 |
| 左、右 | `high` | 第 2、3 行（人站在第 3 行） | 同上，脚下第 4 行、头顶第 1 行 |
| 上、下 | `mid` | 第 9、10 列的**双梯子竖井** | 开口两格和里面一格都是梯子 `H` |

- 左右是两格高的开口，所以就算开口前停着一只箱子，人也能踩着它出去。上下一律是梯子：人在两个房间之间爬上爬下，**不会从一个房间掉进另一个房间**（掉下去会受伤）。竖井是两格宽、左右对称的，翻转后仍然对得上。
- **出入口格对箱子、沙、怪物都是墙**，只有人能走进去离开房间：箱子推不进去，怪物不会走进去，沙落不进去。
- 切片的模板都用 `low` 和 `mid`；`high` 已经在格式和生成器里，留给以后的模板。

## 2 模板格式（`pushbox.room/1`）

模板放在 `content/rooms/<地区>/<编号>.json`，编号全局唯一（`room:<编号>`）。

```json
{
 "format": "pushbox.room/1",
 "id": "dungeon_guard",
 "world": "dungeon",
 "type": "room",
 "name": "守卫廊",
 "idea": "这一间的看点，一句话",
 "weight": 12,
 "mirror": true,
 "exits": {"left": ["low"], "right": ["low"]},
 "routes": ["left>right"],
 "legend": {"1": {"monster": "skeleton_guard", "dir": "left"}},
 "caps": {"top": [[9, 0, 2, 6, "#"]]},
 "mechanisms": ["ladder", "push", "dig", "crush_monster", "trap_monster"],
 "map": ["####################", "..."],
 "notes": ""
}
```

| 字段 | 说明 |
|---|---|
| `type` | `gate` 渡门（起点，正好一个 `gate`）、`home` 收件人之家（终点，正好一个 `recipient`）、`station` 驿站（正好一个 `keeper`）、`room` 普通房间（至少两条边有出入口） |
| `map` | 10 行 × 20 列。字符用关卡模式的图例（`#` 基岩、`e` 夯土、`s` 散沙、`.` 空、`H` 梯子、`B` / `I` 木箱 / 铁箱、`_` 压板、`\|` 门），另加 `$` 金币和 `legend` 里的数字。不能用人物、箱子槽、出口旗和第 2 组以后的材料（切片地区没有水） |
| `legend` | 数字 → `{"monster": 怪物编号, "dir": "left" / "right"}` 或 `{"feature": "gate" / "recipient" / "keeper"}`。脚下要有地面；怪物离任何出入口格至少 4 格 |
| `exits` | 每条边上有哪些口位。生成器只打开它要用的那几个，其余的**封上** |
| `caps` | 封口时额外改写的方块 `[x, y, 宽, 高, "字符"]`（例如上面的竖井不用时，把竖井上半截变成墙）。不写时只把开口那几格填成基岩 |
| `routes` | 单向房间才写：保证走得通的方向，如 `"left>right"`。不写 = 任意两个出入口双向都通 |
| `mirror` | 可以左右翻转（地图、出入口、怪物朝向、`routes`、`caps` 一起翻） |
| `weight` | 生成器挑模板时的权重，默认 10 |
| `links` | 压板与门的配对，同关卡规格；不写时所有压板控制所有门 |
| `demos` | 演示输入：一段按键脚本和应有的结局，用实时规则回放（[delivery-realtime.md](delivery-realtime.md) 第 12 节）。每个模板都应该有（普通房间没有时，检查会提醒） |

切片的 10 个模板（石牢）：渡门、收件人之家、驿站，以及普通房间：石廊（推怪）、守卫廊（压怪、困怪）、鼠洞（挖穿土丘）、机关门（推箱进压板坑，单向）、竖井、转角、废井。工作台「地图预览」左栏可以逐个查看。

## 3 地图生成（`mapgen.js`）

同一个种子 + 同一个切片 + 同一组模板 = 同一张地图。全部是整数运算；**取随机数的顺序也是规格**，移植时必须照抄。

1. **随机数**：xorshift32。状态 = `(种子 ^ 0x9E3779B9)` 取 32 位无符号，为 0 时改成 1，先空转 4 次。每次 `x ^= x << 13; x ^= x >>> 17; x ^= x << 5`（都按 32 位无符号）。`int(n)` = 下一个数 `% n`。种子是小于 2³¹ 的正整数。
2. **方向**：`directions[int(方向数)]`，切片是 `down`（从上往下）或 `up`（从下往上，各一半）。
3. **蛇形路径**（照 Spelunky 的主路径）：起点在最上一行的 `int(列数)` 列，横向方向 `int(2) ? 右 : 左`。不在最后一行时：前面出界或走过，就下降一行（这时**不取**随机数）；否则取 `int(100)`，小于 `drop_pct`（30）也下降；下降后用 `int(2)` 重新取横向方向；不下降就横走一格。在最后一行：前面走不了就结束（不取随机数），否则取 `int(100)`，小于 `end_pct`（20）就结束，不然横走一格。路径长度不在 `path_min`–`path_max`（5–9）之间就重新生成（最多 200 次，随机数接着往下取）。方向是 `up` 时把路径上下翻过来。
4. **角色**：第一间是渡门，最后一间是收件人之家，第 `⌊(长度 − 1) / 2⌋` 间是驿站，其余是普通房间。路径之外的格子是封死的，玩家永远到不了。
5. **挑模板**（深度优先，走不通就退回上一间重新挑）：对第 i 间，按权重把这个角色的模板排成一个顺序（每次按权重抽一个，不放回），和上一间相同的模板挪到最后；对每个模板，能翻转时用 `int(2)` 决定先试翻转还是先试不翻；进来的那条边必须有上一间选定的口位，`routes` 必须允许"从进来的边到出去的边"；出去的那条边上的口位按 `int(个数)` 排顺序逐个试，再往下一间递归。
6. **结果**（`pushbox.map/1`）：`seed`、`slice`、`cols`、`rows`、`dir`、`attempt`、`path`、`rooms`（每间：`x`、`y`、`index`、`role`、`template`、`mirror`、`open` = 打开的口位）。

前 30 个种子的结果写在 `content/export/delivery-golden.json`。游戏的生成器必须对这 30 个种子给出完全相同的结果，测试里逐个比较。

## 4 可通性检查（`node tools/check-rooms.mjs --write`）

1. **静态检查**：尺寸、边框、口位形状、字符、`legend`、怪物离出入口的距离、每种房间的必备要素、`routes` 和 `caps` 的写法。
2. **每一种摆法都走一遍**：一个模板在地图里可能的摆法 = 翻转与否 × 打开哪几个出入口（渡门和收件人之家各一个；普通房间和驿站各两个）。每种摆法都按封口后的样子检查：普通房间两个出入口之间互相走得通（单向房间只查允许的方向）；渡门从门口走到出口；收件人之家从入口走到收件人旁边；驿站两边都走得通，而且从每个入口都能走到龟掌柜旁边。
3. **怎么算"走得通"**：用关卡模式的格子模型（`tilemodel.js`），**沙袋为 0、不用道具、没有怪物**；先只用走、推、爬，不够再加挖和倒；**任何一次下落 3 格及以上、落点不是沙，都不算**（配送模式里会掉心）。出入口格当成墙（只有人能走），所以走到出入口里面那一格就算到了。
4. **按种子生成**：用切片的模板生成 300 个种子的地图，每一间的摆法都必须在第 2 步里检查通过。
5. **参考用时**：每条路线按动作计时（走、爬 13 刻，推 18，挖、倒 21，下落每格 5 刻；每秒 60 刻），再加 25% 和 1.5 秒，向上取到 0.5 秒。一张地图的参考时间 = 主路径上每间实际要走的那条路线的参考用时之和，用来算小费的用时系数（[delivery-slice.md](delivery-slice.md) 第 10 节）。
6. **输出**：`content/rooms-check.generated.json`（每个模板的每种摆法、每条路线的步数、是否要挖、参考用时和动作序列；每个切片的路径长度分布、方向、模板使用次数、参考时间范围）和 `content/export/delivery-golden.json`。模板文件改了而没有重新检查，`node tools/content.mjs check` 会报错。

**这个检查证明不了的**：怪物、时间、受伤（由实时规则和每个模板的演示输入负责，见 [delivery-realtime.md](delivery-realtime.md)；同一个工具会把全部演示跑一遍），以及 SDK 里沙的真实表现（开发方在 Godot 里验证）。

## 5 工作台「地图预览」

- 左栏：种子（上一个、下一个、随机）、显示路线开关、房间模板列表与检查结果。
- 中间：整张地图的总览（每格 4 像素；封死的格子画斜线；路径用黄色连起来；角标是第几间，颜色表示渡门 / 驿站 / 收件人之家），点一间就在下面用主题画出这一间，黄色虚线是检查工具找到的路线。
- 右栏：这张地图的种子、方向、路径长度、参考时间，每一间的模板和出入口。
- 点模板进入模板页：所有摆法和每条路线的步数、是否要挖、参考用时。
- 怪物（R 鼠群、S 骷髅守卫）、渡门 G、收件人 D、龟掌柜 K、金币 $ 目前是**占位**（字母方块），美术在第 4 步画、用户确认后才换。配送模式里石牢的小老鼠生态关掉了（`worlds.json` 的 `ambient_exclude`），免得和怪物混淆。
