# 横版关卡与机制重设计草案

更新日期：2026-10-15（Asia/Shanghai）。阶段：文档设计 v1，供讨论与后续逐关细化使用。

本项目全程采用横向画面、侧视重力与推箱解谜，不引入俯视章节。现有地图和关卡均按实验原型处理，可以重新设计。本方案以易读、容易尝试、没有操作压力的主线为目标：先组织现有 SDK 的横版能力，再搭配直观的游戏层机关，真正需要扩展 SDK 的能力留到之后。

建议保留地牢、森林、遗迹、洞穴、天空岛、宇宙六种主题，每主题编排 6 个轻量主线房间和最多 2 个选修房间，首轮预算为 **36 个主线关、12 个选修关，共 48 关**。48 是内容预算；没有独立教学或探索价值的房间可以删减，不为凑数增加难题。本文件集中记录范围、参考依据、机制、难度、48 个关卡概念和验收原则，不另拆多份新设计稿。

本稿替代本文件旧版的固定 36 关设计，也替代此前“6 个横版章节加 2 个俯视章节”的建议。历史实现和旧作者解法保留其历史意义；下文概念尚未变成地图几何、运行代码或有解性证明。

## 1 设计目标与现有问题

### 1.1 主线体验

玩家先看懂房间，再做一个有把握的尝试，立即看到因果关系。主要乐趣来自发现“这个物件还可以这样用”，而不是反复搬运、猜隐藏规则或抢时机。解法可以很短，只要这个发现有意义。

玩家仍按步移动、推箱、挖取、倾倒、使用机关和爆破。物理变化在动作提交后播放，播放完成后停下来思考。新增机关优先复用现有交互，不为每种装置增加一个按键。主线不要求跳跃、空中操控、连续点按、同时操作两个角色或在倒计时内跑过机关。

### 1.2 原型暴露的问题

现有 36 关的作者动作序列为 6–66 步，中位数为 21 步；D_06、R_06 各有 66 步，部分房间需要长距离往返和多段竖向搬运。这些是已记录路线的长度，不是最短解，也不能单凭步数判定难度，但提示需要检查“思考之后还有多少重复执行”。

机制审核还发现：去掉 R_02 的沙漏、分别去掉 C_06 的间歇泉或钟乳石、去掉 S_05 的冰冻，原作者路线仍能通关。机关会播放效果，不等于玩家需要理解它。新版每关必须写清核心发现和机关用途，避免用装饰性机关充当机制覆盖。

本轮以用户“有些关卡过难”的反馈为改版依据。复杂机关链、规则缺少单独教学、目标不清和重复操作是待试玩检验的设计假设，不预先把全部问题归因于某一个因素。

### 1.3 内容规模取舍

| 方案 | 好处 | 代价 | 本稿选择 |
|---|---|---|---|
| 六主题各六关 | 规模较小 | 教学、巩固与组合容易挤在同一关 | 不作为数量硬约束 |
| 六主题各六主线加两选修 | 主线保持轻量，给物理实验和规则变化留空间 | 需要主动删除重复关 | 采用，最多 48 关 |
| 每个新机制各开一张地图 | 分类直观 | 美术与教学重复，章节膨胀 | 仅形成独立玩法体系时采用 |

## 3 难度与教学规范

### 3.1 房间职责

每关必须属于教学、巩固、轻组合、探索或缓冲中的一种，并用一句话说明玩家会学到什么。教学关只增加一个新概念；巩固关只改变一个条件；主线组合关最多需要两个关键决策。推箱入终点等机械收尾不计作额外发现，但应尽量短。

每章前两关建立安全感，中间两关拓展用途，后两关温和组合。选修关不能承担下一章默认玩家已经掌握的必备知识。后续章节若使用玩家可能跳过的概念，必须在当前房间提供短演示和规则卡，不要求回头补一串前置关。

### 3.2 主线的设计预算

| 项目 | 教学与缓冲关 | 一般主线关 | 选修关 |
|---|---|---|---|
| 活动区域 | 约 8×5 至 10×6 格 | 约 10×6 至 14×8，收束关可到 16×9 | 通常不超过 20×11 |
| 目标物 | 优先一个箱子或一个接收目标 | 通常不超过两个 | 通常不超过三个 |
| 核心发现 | 一个 | 一个，最多两个连续决策 | 最多三个，全部可观察 |
| 作者路线目标 | 约 4–12 次输入 | 约 8–24 次输入 | 服从想法，仍删除无效往返 |
| 初次游玩目标 | 约 30–90 秒 | 约 1–4 分钟 | 约 3–6 分钟，可随时离开 |
| 不可逆选择 | 首次不设置 | 优先零个，必要时一个且可撤销 | 明确提示，仍可撤销与重开 |

这些是后续设计与试玩调整目标，不是已测得的玩家表现。不能为压步数删掉必要教学，也不能用“未超步数”替代可读性检查。

### 3.3 降低认知与执行负担

- 目标、控制器和受控对象尽量同屏；用形状、配对符号和连线表达关系，不能只靠颜色。
- 首次教学只有一个明显有效的交互。装饰不能像可操作物，背景不能遮住沙路、水面或门状态。
- 主线不设屏外连锁、未知重量、隐形触发、黑暗找机关或精确水量猜测。
- 输入按格吸附；喷口、接料斗和落物目标有宽容区域，不需微调像素。
- 箱子误推入角落后可立即撤销。落水、困住或失败不扣资源、生命或通关评价。
- 沙袋和炸药按清楚用途配给，不以不透明的稀缺资源逼玩家找最优解。
- 重复运输尽量一次完成；已经走过的竖井和绕路不作为后半关主要内容。

### 3.4 提示与练习

提示由玩家主动打开，不因停留时间强制打断。第一层突出相关目标；第二层说明因果；第三层展示可重置的小演示；玩家仍可主动查看明确的下一步或完整解法。使用提示照常通关，不降低解锁资格。

提示必须匹配当前局面。不能可靠解释偏离作者路线的状态时，应引导撤销到已知节点或重开演示，不能把开局作者动作套在任意状态。简化演示复用规则，不另算主线关数。

## 4 世界推进与目标规则

### 4.1 回合与物理播放

普通沙水关采用“提交动作、播放变化、停止观察”。热学、电路、寿命等持续变化关使用关卡固定的有限模拟阶段；允许等待指令，但阶段长度、结束条件和可见效果须在设计时确定。玩家看到装置阶段与结果，无需理解 tick 或求解器统计。

不能把纯温度变化误判为完全静止，也不能让持续电路一直阻塞操作。触及安全上限属于异常，不算正常结束。只能靠等待随机时长或抢在变化中输入才能解开的房间，退回重设计。

寿命、燃烧、相变和反应由 SDK 内容配置执行。脚本可表达按钮、导流选择、目标与阶段，但不逐帧伪造燃烧或流体自然过程。自然水源／气源优先用内容与耦合器；首版优先有限储槽和玩家触发的一次释放。

### 4.2 目标形式

推箱归位仍是主要目标，也可使用接料、疏通、保护固定结构、把物理重物送入接收区等目标。目标始终可见，主线一次只强调一个目标，不给物理演示硬加一段无关搬箱。

接料统计沉积后的材料量；气体接收、反应完成和通电目标在模拟阶段内查询，成功后锁存，避免门随瞬时信号闪动。具体数值由样板验证；玩家看到“够一份材料”和清楚刻度，不需要猜像素阈值。

### 4.3 推进与选关

保留每主题主线通关任意 3 关即可进入下一主题的门槛，不因扩为八关而提高要求。六个主线房间可自由尝试，界面给出推荐顺序；后两关标为选修，不计跨图门槛。全部关卡可观察，并保留自由选关设置。

跳关进入的房间须能就地补看规则。首章基础操作也有独立入口，避免玩家重开档才能复习。选修奖励只用于收藏与探索，不提供主线必需的工具或资源。

## 5 现有 SDK 横版能力覆盖

基线为项目绑定的 ele-base-cpp v1.2.0，提交 dacb93e。排除俯视用途的 surface_water、gas_field、regions，不再以运行全部 13 个求解器为目标。玩法覆盖与碰撞、渲染、快照等支撑能力分别核验。

| 编号 | 现有能力 | 教学与后续应用 | 设计边界 |
|---|---|---|---|
| N01 | 粉末下落、堆积、慢速移动 | D03、D04；D08 | 粉末不自动水平输送；挖取／倾倒属游戏行为 |
| N02 | 液体流动与密度置换 | R01、R02；R05 | 格箱上浮由游戏判定，不称为 SDK 刚体浮力 |
| N03 | 连通器液位平衡 | R03；R05 | 保持液面开口，不能靠顶盖原生挤起格箱 |
| N04 | 邻接反应、标签匹配 | F01、F02；F07 | 普通反应无方向和温度条件；刚体像素不参与 |
| N05 | 上升／下沉气体 | F03、F04；F08、S02 | 用横版 gas 材料，不用俯视浓度场 |
| N06 | 材料寿命与转化 | F05；F07 | 到期变化由材料配置执行，不考抢时间 |
| N07 | 爆炸、抗爆性与破坏 | C01；C05、C07 | 爆炸无墙体遮挡，保护靠抗性／距离，预览如实显示 |
| N08 | 导热、恒温源与降温 | C02、C03；C06 | 小规模验证响应速度，不让玩家盲等 |
| N09 | 真实温度相变 | C03；C06、C08 | 与 layer 装置直接改材料分开标注 |
| N10 | 燃烧与灭火 | C02、C04；X03、X06 | 灭火不自动降温；先断持续热源，再验证余温不会复燃 |
| N11 | 引信与连锁爆炸 | C05；C07 | 点燃后观看，不在引信期间要求跑位 |
| N12 | 气压传播与气体漂移 | S01、S02；S06 | 气压不直接吹格箱／刚体；先用有限压力脉冲 |
| N13 | 定向粒子与落地沉积 | S03、S04；S06、S08 | 判定沉积物，不承诺飞行粒子命中事件 |
| N14 | 真实刚体掉落、冲量、碎裂 | R07、R08；C07 刚体版本 | 与格箱区分，先验证撤销、重放和目标容差 |
| N15 | Wireworld 电源、导线、火花 | X01、X02、X03 | 电控门是游戏层读状态，不是 SDK 原生逻辑门 |
| N16 | 自定义层与三类耦合 | X04、X05、X06 | 分别覆盖 layer 改材料、材料写 layer、layer 灭火；阈值不等于邻居条件 |

contours 是连续角色地形碰撞支撑。当前人物按格移动，不仅为增加求解器数量更换整套操作；若以后需要连续角色在物理地形上行走，再验证碰撞代理。刚体的内部地形碰撞不等于已经接入角色代理。本版先让刚体在安全接收装置中完成目标，不要求人站在运动刚体上。

N14 仍属于老 SDK 范围，放在选修实验房以免阻断主线，不代表省略技术验证。未做成前不能宣布老 SDK 横版能力已全部覆盖。索引表也不等于逐关用途已经得到运行证明。

C07 的刚体碎裂版本也属于本轮老能力范围，须先通过 R07 的重放样板。它不是等待新 SDK 的追加项；若该版本尚未做成，应明确保留“刚体碎裂未覆盖”，不能用普通裂岩爆破顶替。

## 6 可加入的游戏层机关

这些机关不需发明 SDK 求解器，但需要游戏代码、状态保存和验证。规则在确定的结算边界执行，与材料变化通过命令／查询衔接。自然过程仍优先用内容配置。

| 编号 | 机关 | 玩家看到的规则 | 首版限制与位置 |
|---|---|---|---|
| P01 | 压板与配对门 | 人或箱压住同符号板，门开启 | 先单板单门；D05、D06。离板仍开门须显示锁存灯 |
| P02 | 两停靠点升降台 | 放好箱子再按按钮，到另一站停住 | 不自动往返、不追平台；R04，两站同屏 |
| P03 | 配重托盘 | 木箱一份、铁箱两份，到刻度便升到固定站 | 明示重量，不连续摇摆；R06，先不用散沙猜重量 |
| P04 | 单向翻板 | 沿箭头通过，反向被挡 | 首次有回收路；同类角色／格箱规则一致；D07。首版不改变流体通过规则 |
| P05 | 接料斗与锁存 | 装够一份，完成灯保持亮 | 宽收口、有刻度，接满后不抖动；F03、S03、S06 |
| P06 | 两位置导流槽 | 停机时选左／右出口，再释放材料 | 不在带料播放中切换，不做精准反弹；S04、S08 |
| P07 | 遇水藤梯 | 水到标记根部，出现固定高度的梯子 | 离散机关，不冒充植物模拟；F06，首版只供人物攀爬 |
| P08 | 轻重云垫 | 木箱和人物被托住，铁箱穿过 | 明示轻重，首次有安全底板；S05、S07 |
| P09 | 电信号转机关 | 导线脉冲让配对装置执行一次并亮灯 | 单输入／简单双条件，不做不透明逻辑网；X01、X02 |
| P10 | 固定配对传送 | 可传物进入入口，在标记出口出现 | 仅冷态格箱／普通沙，出口占用则不启动不消耗；X07 |
| P11 | 镜像联动小车 | 两条水平轨道以中央竖线配对；左车右移一格时右车左移一格，纵向不动；任一端挡住则都不动 | 控制台复用方向输入与确认，两端同屏、标出镜像轴、不复制物料、不同时按键；X08 |
| P12 | 局部装置重置 | 一次恢复装置及关联材料、容器、完成灯 | 只用于边界封闭的独立装置；无法追回跨区物料时整关重开，不凭空补料 |

先采用 P01、P02、P05、P06 等便于表达的装置。镜像、传送和复杂配重留到后段，不把每个房间都塞满机关。回合沙漏、磁性吸附、局部反重力、旋转房间和可编程机器人暂列储备；主线试玩后再决定，不能自动变成新增地图与本轮任务。

## 7 六主题关卡概念

D01 等是新版文档编号，不等于现有 D_01 等生产文件。每条是可讨论的谜题骨架，空间坐标、资源量、作者解法需后续细化。主线难度为一至三档；选修可以是轻松实验，也可以是深入变化，不统一等于高难。

### 7.1 地牢 认识箱子与沙

| 编号 | 定位 | 核心发现与预期顺序 | 目标与防难度措施 |
|---|---|---|---|
| D01 一推就到 | 主线教学 1 | 把一个木箱沿直路推入目标凹槽 | 单箱无死角；学归位与撤销，不夹带沙水 |
| D02 绕到另一边 | 主线巩固 1 | 沿短梯绕到箱子另一侧再推 | 只教站位；画清人物能登阶、箱子不能登阶 |
| D03 挖开一格 | 主线教学 1 | 挖掉一格挡路沙，再推箱通过 | 沙袋立即反馈；不藏第二处沙源 |
| D04 一袋填平 | 主线教学 1 | 用现成一袋沙填浅坑，再推箱 | 不先找沙；落点吸附清楚，溢料不致失败 |

## 8 三个房间的设计卡示例

### 8.1 D04 一袋填平

一句话发现：沙可以把箱子不能跨过的浅坑变成通路。

开局只有人物、一个箱子、一个浅坑和一袋现成沙。箱在坑左侧，目标在右侧，人有安全站位。先观察箱不能过坑，再向标记口倾倒，沙稳后推箱。没有远处沙源、第二个坑和分类背包。

提示依次是“注意箱路的凹处”“沙落下会留下支撑”“在标记口倒这一袋沙”。验收须确认倒料有容差，散沙不会让目标无法恢复，撤销可完整取回这一袋。

### 8.2 R04 平台等我上

一句话发现：平台可先布置、后启动，不需要追着跳。

平台有上下两站，箱在下站，上站有短平直目标区。按钮与平台同屏。人先把箱推上去、按按钮，停稳后在上层推到目标。人物有固定梯子去上站，平台也可返回；不把唯一按钮藏到平台后面。

到站一直等待。载物受顶面／侧面阻挡时清楚拒绝移动，不挤压、吞箱或把人卡入地形。这是游戏层搬运装置，不用它冒充真实刚体测试。

### 8.3 S03 沙粒落进斗

一句话发现：粒子落地后仍是可收集材料。

喷口固定，料斗宽且有导向边，不让玩家调角度。一次释放足量物料，阶段结束后超过明确最低线，完成灯保持亮。判定沉积沙，不是飞行中碰到某像素。

样板核对掉落变化、残留与溢出。只有精细参数才勉强接住时，扩大接收区或改几何，不要求精确按键。之后 S04 只改变导流路径，验证理解运输关系。

## 9 接入现有能力必须处理的边界

| 风险 | 设计要求与后续验证 |
|---|---|
| 热学／电路不适合当前静止判定 | 明确有限阶段与等待动作，测试阶段末结果和重复执行，不把超时当完成 |
| 刚体快照恢复不保证后续位级一致 | 从无刚体初态完整重放命令时间线是待验证方案；通过前 R07／R08 不宣称撤销／预演已支持 |
| 格箱与刚体混淆 | 造型、目标、交互区分，刚体只在封闭装置中运行 |
| 脚本删旧格再画新格丢状态 | 首版不搬高温、燃烧、带寿命材料与导体；材料数量守恒不代表温度／燃烧计时也无损 |
| 冰桥有不同实现 | thermal 相变、couplers 装置与旧脚本换材质分开标记；X04 使用不带 phase_up 的独立装置冰或无 thermal 的关卡 profile，不能把室温水换成带融化相变的冰后指望它保持 |
| 恒温字段不能直接制冷 | hold_temp 只把温度托到最低值，不提供冷却上限。C03／C06／C08 用玩家触发的 temperature 写入或经验证的有限预冷介质；后续变化由 thermal 相变执行，验证整个解题阶段的冰桥保持时间 |
| 灭火后余温仍高 | C04 必须验证水与阶段能把目标降到复燃阈值以下；X06 的 layer 灭火保护保持到目标阶段结束，不能声称灭火已经降温 |
| 休眠水体不知新通路 | 验证开闸、箱子离开和液位，使用明确兼容做法；无损唤醒另属工程改进 |
| 反应／相变／入区无对应事件 | 阶段内查询、一次目标锁存，状态纳入撤销与重开 |
| SDK 快照不含游戏状态 | 另存平台、门、配重、藤梯、接收计量、联动等；不能只比世界 hash |
| 主线依赖原始阈值 | 留容差、展示刻度，不以 cell 数、温度整数和 tick 数作为默认解题知识 |

每关只启用所需求解器，不将全部机制同时塞进一个房间。原型运行默认单 worker，启动前检查全机共享预算；本轮文档设计不运行物理或压力测试。

## 10 真正的新 SDK 能力以后追加

火、冰、电路、毒气、引信、刚体、气压和粒子都是老 SDK 应用，应先完成相应样板与关卡。新增脚本机关按谜题价值选用，不需要等待底层扩展。

| 后续能力 | 状态与区别 | 优先追加位置 |
|---|---|---|
| 液体流量读数 EXT-06 | 已有扩展草案，测经过量而非区域存量，最初服务塔防 | 遗迹追加水车／连续用水关 |
| 方向性反应 | 候选，指定方向接触才反应，区别普通四邻接反应 | 森林追加滴灌／单向腐蚀关 |
| 温度条件反应 | 候选，两材料相邻且温度合适才反应，区别已有单材料相变 | 洞穴追加受控炼制关 |
| 原生持续风源 | 候选，材料持续产生气压，区别已有传播／玩家脉冲 | 天空追加持续风路关 |

每项新玩法先追加安全教学、变化、必要时组合共 2–3 关。只有形成独立空间组织或足够多独特关卡才考虑新地图，不按新增接口数增加地图。追加时仍保持侧视。

静止查询 EXT-03、无损唤醒 EXT-09、渲染瓦片边缘 EXT-10、按 tag 过滤画笔 EXT-11 是工程改进，不各占地图。成为老能力可靠接入的必要修复时应明确列技术前置，不能先把故障房算完成。已撤销或未提出的其他需求不自动恢复为任务。

## 11 逐关细化与验收

### 11.1 每房下一步补齐的内容

概念进一步细化时须补齐：教学职责、已知规则、唯一新增概念、可操作物、可见目标、空间草图、材料／机关初态、资源、预期解法、替代解允许范围、三层提示、常见误解、恢复方式和验证条目。缺少这些内容不直接批量生成地图文件。

核心机关禁用后原路线仍成功时，应判断是合理替代解、刻意背景，还是机关无作用。无关机关增加负担就删除。禁用导致原路线失败只说明路线受影响，不证明所有其他解都不可能。

### 11.2 三层验收

| 层次 | 要证明什么 | 不能替代什么 |
|---|---|---|
| 设计审阅 | 职责清楚、跳关可补知识、难度预算合理、覆盖无错位 | 不证明几何布局有解 |
| 技术验证 | 真实解法通关、重复一致、撤销／预演完整、无异常阶段、资源／物料正确 | 不证明新手觉得容易 |
| 新手试玩 | 看懂目标与因果、愿意尝试、失败后可继续 | 不替代技术和性能门禁 |

首轮建议至少 5 名不熟悉本项目的玩家，观察教学与一般主线，记录首次有效操作、停顿处、提示层级、失败原因和解后解释。两名玩家在同处误解，优先改表达／布局。这个样本用来发现明显问题，不作为难度普适性的统计证明。

初步目标为教学关大多数参与者两分钟内能解释规则，一般主线尽量四分钟内完成或借前两层提示继续。超目标先查信息、前置教学和执行负担，不先怪玩家，也不只加文字掩盖布局问题。

### 11.3 后续顺序与执行人

1. 当前 Codex 先补齐六个最简单机制样板房的空间与因果草图，覆盖地牢基础、森林反应、遗迹水位、洞穴热学、天空气压／粒子、宇宙电路；另为真实刚体单列 R07 的技术设计卡。本轮不实现或运行。
2. 设计卡审阅后，再由执行 Codex 做兼容性样板。可用后逐章细化，先教会规则再做巩固与组合，不先堆 48 张地图。
3. 开发阶段由执行 Codex 制作关卡与技术验证，用户及新手试玩者反馈体验。作者回放通过不记为玩家验收通过。
4. 老 SDK 横版范围与必要脚本机关完成后，再选择第 10 节新能力，并优先向原主题追加关卡。

本次交付停在统一设计草案，未启动关卡重做、SDK 扩展或代码修改。最近可执行的设计工作是细化样板房草图，由当前 Codex 接续；当前无需用户立即操作，阅读后可在本聊天提出修改意见。
