# 美术规范（AD-1）

适用于全部游戏美术与界面。规范只描述规则；每件资产的具体版本和确认状态以 `art/` 中的数据与确认记录为准（见 [美术流程](art-pipeline.md)）。

## 1 原则：玩法信息优先

画面上的视觉强度按以下顺序递减。任何装饰都不能比它的上一级更醒目：

1. **人物**：唯一的暖色高饱和组合（黄帽、红衣），四周 1px 深色描边。
2. **可操作物与目标**：箱子、门、压板、目标槽、出口旗、收集斗。用清楚的轮廓和形状区分，配对关系用**形状符号**（圆、三角、方块）表达，颜色只作辅助。
3. **会动的材料**：沙、水、酸、烟、火、冰。每种材料必须同时在色相和纹理上与其他材料不同（不能只差明度）。
4. **静态地形**：基岩、夯土、裂岩。顶面 1px 受光边，底面 1px 阴影，不加黑色描边。
5. **背景与装饰**：低对比、偏冷、偏暗；任何背景像素都不能比同一区域地形的中间调更亮；不出现与可操作物形状相近的装饰。

## 2 规格

| 项 | 规定 |
|---|---|
| 逻辑画面 | 320×180，整数放大，最近邻采样，不做亚像素位移或抗锯齿 |
| 格子 | 16×16；人物、箱子和机关精灵为 16×16，有需要时可用 16×32 或 32×16 |
| 锚点 | 精灵锚点为底边中心 (8,16)，与所在格的底边对齐；界面元素锚点为左上角 |
| 调色板 | ENDESGA 32（作者 Endesga，公开免费使用），源数据用单字符 `a`–`z`、`A`–`F` 编码，`.` 表示透明 |
| 光照 | 主光来自左上；立体物件右下侧暗一级 |
| 描边 | 人物、箱子、可拾取物用 `z`（#181425）描边；地形与背景不描边 |
| 动画帧率 | 人物动作 8 fps；环境与装置循环 4 fps；界面过渡按整数像素移动 |
| 字体 | Fusion Pixel 12px（OFL），最近邻渲染，关闭抗锯齿与 hinting；正文行高 14px |
| 图标 | 16×16；按键图标 13×13 |
| 面板 | 九宫格，角 6px；面板底色不透明，不用渐变 |

## 4 动画清单要求

- 人物：待机 2 帧、走 4 帧、推 4 帧、爬 2 帧、挖 3 帧、倒 3 帧、落 1 帧、胜利 2 帧；左右镜像共用。
- 机关：门开 / 关各 4 帧；压板按下 1 帧；目标灯亮 2 帧循环；收集斗刻度。
- 反馈：受阻抖动（人物左右 1px，2 帧）、灰尘（落地 3 帧）。

## 5 地形着色规则（游戏内由着色器实现）

地形逐 cell（=逐像素）着色。HTML 中的实现在 `workbench/js/core/terrain.js`，它就是规范：

- 静态材料（基岩、夯土、裂岩）的颜色只由材料、像素位置哈希 `h32(x, y, 材料种子)` 以及上下左右的同类关系决定。游戏着色器必须使用同一哈希公式，以保证逐像素一致。
- 沙、水等会移动的材料在游戏中使用 SDK 的随机颜色位（随格移动），与 HTML 只比对颜色集合，不要求逐像素一致。
- 受光边：上方为空（或非同类）的格画 1px 亮色；阴影边：下方为空的格画 1px 暗色。
- 水面：上方为空的水格画 1px 亮线，水体比静止背景亮。

## 6 不做的事

- 不用 AI 风格的光晕、渐变、柔边、高斯模糊、半透明叠加光束。
- 不用颜色作为唯一的配对信息。
- 背景中不出现可能被误认为可操作物的方块形物件。
