## 1 解谜原则

1. **每间房只教或只用一件事**。`role` 是这间房在一局里的位置：`teach` 只教一个新东西（写在 `teaches`）；`develop` 把教过的东西用深一层；`twist` 把两样学过的东西拧在一起，出一个意外；`breather` 是过道（没有谜题，有怪物和金币）；`gate`、`station`、`home` 是起点、驿站、收件人之家。`idea` 写两句：「关键想法：……变化：……」，房名点出关键想法（「断桥 · 推浮石」）。
2. **先教后用**：房间的 `needs` 必须已经被这一局前面某间房的 `teaches` 教过，生成器才会选它（第 6 节）。
3. **怪物不进解谜区**：`puzzle_area` 圈出解谜的格子（可以几块），怪物的巡逻范围（legend 的 `zone`）不能和它重叠（`monsterProblems`）。解谜时不被追，对付怪物在过道里。
4. **必需机制**：`requires` 里的每一项（只能是 `float_block`、`pole`、`push`、`dig`、`pour`、`lever`）关掉以后这间房必须走不通——检查工具把它冻结再搜一次。所以"教撑篙"的房间不撑篙就过不去。
5. **不靠摔**：人落下 3 格或以上（`FALL_HURT = 3`）算摔伤，检查和作者解都不允许这一步；落在沙上不算。任何路线都不用掉心。
6. **每条路线都走得通**：房间写明检查过的 `routes`（`入口>出口`）；每种翻转、每条路线都要有最短解；写了作者解（`solutions`）的路线，作者解也要走通。
7. **提示和解法一致**：提示步骤要按作者解（没有就用最短解）的先后依次完成（第 5 节）。

## 2 房间格式 `pushbox.room/2`

一屏 20 × 10 格，一格 16 px。`size` 是屏数（宽 × 高）：`1x1`、`2x1`、`1x2`、`2x2`，即 20 × 10 到 40 × 20 格。

| 字段 | 含义 |
|---|---|
| `format` | 固定 `"pushbox.room/2"` |
| `world`、`id` | 地区、房间编号（`dungeon2_bridge`、`diyu_fengdu`……） |
| `type` | `gate` 起点 / `home` 收件人之家 / `station` 驿站 / `room` 普通房；起点要正好一个渡门，收件人之家正好一个收件人，驿站正好一个掌柜，普通房不能有这些 |
| `role` | 第 1 节的七种 |
| `size` | `[列屏数, 行屏数]` |
| `name`、`idea` | 房名、关键想法 |
| `needs` / `teaches` / `requires` | 要先学过的、这间教的、必需的机制（第 1 节） |
| `mechanisms` | 房间里出现的机制（展示用） |
| `exits` | 出入口 `<边>.<屏段>.<口位>`。边 `left` / `right` / `top` / `bottom`；屏段从 0 数（2 屏宽的房间上边有 `top.0`、`top.1`）；左右的口位 `low`（第 6–7 行开口、第 8 行是地面）或 `high`（第 2–3 行开口、第 4 行是地面），上下的口位 `mid`（第 9–10 列的双梯子竖井）。普通房至少 2 个，起点和收件人之家至少 1 个 |
| `routes` | 检查过的走法 `"入口>出口"`；`gate` = 从渡门出生，`recipient` = 走到收件人面前 |
| `puzzle_area` | 解谜区矩形 `[x0, y0, x1, y1]` 的数组 |
| `links`、`devices` | 压板 / 按钮 / 拉杆与门、吊篮的连接；吊篮、承重桥等装置。写法同关卡模式 |
| `legend` | 地图里的数字 → `{monster, zone: [x0, x1], dir}`（怪物、巡逻范围、起步方向）或 `{feature}`（渡门、收件人、掌柜、提示动物……） |
| `hints`、`hint_route` | 提示步骤和它针对的路线（第 5 节） |
| `solutions` | `{路线: [动作…]}` 作者解。动作 `L R U D DIG_L DIG_R DIG_D POUR_L POUR_R`，`R*5` = 连按 5 次 |
| `caps` | 用不到的出入口怎么封（同 v1） |
| `only` | `{recipients: [...], cargo: [...]}`：只给这些收件人 / 货物用（收件人之家用它分住处） |
| `weight` | 被选中的权重（默认 10） |
| `mirror` | 能不能左右翻转（默认能） |
| `map` | 地图，每行一个字符串 |

**地图字符**：关卡模式的地块字符 `# % e s . H B I _ | ~ =`（岩石、裂石、土、沙、空、梯子、木箱、铁箱、压板、门、水、承重桥……，与关卡模式完全相同）；`F` / `G` = 浮块（两块挨着时用不同字母分开）；`$` = 金币；`0`–`9` = `legend`。

**校验**（`validate`）：行列数对；每个字符都认识、数字都写在 `legend` 里；边框是基岩（出入口除外）；出入口格是空的（上下竖井是梯子），左右开口的脚下和头顶是基岩；出入口写法和屏段号合法；浮块每段 2–4 格宽；至少一条 `routes`，用到的出入口都存在；`zone` 写成 `[x0, x1]`。

**翻转**（`variant(room, mirror, open)`）：左右镜像时 `left` ↔ `right`、屏段倒过来数，`legend` 的 `zone` 和 `dir`、`devices`、`puzzle_area`、提示里的坐标和方向一起翻（`mirrorExit`、`mirrorPred`），作者解的 `L` ↔ `R`、`DIG_L` ↔ `DIG_R`、`POUR_L` ↔ `POUR_R`（`mirrorActions`）。用不到的出入口按 `caps` 封上。

例（`dungeon2_bridge`，1×1，教浮块；`F` 是 4 格宽的浮石，作者解 `R*19` 是"一路按右"：推浮石推到撞上石柱，再踩上去走过坑）：

## 3 浮块与撑篙

浮块（`float_block`）是悬在空中、永远不掉的一段地块，2–4 格宽、一格高。石牢是符文浮石（`mech.rune_float`），地府是孔明灯吊着的纸台（`mech.lantern_float`）。

**在格子模型里**：`start()` 把 `F` / `G` 当岩石，位置记在 `s.floats = [{n, x, y, w}]`；人、箱子、沙都能站在上面，移动时只改这几格。

**推**（`moveFloat`）：人站在浮块的左边或右边，朝它走（`L` / `R`）：
1. 浮块移动方向上的下一格必须是空的、干的（不是水），没有箱子、人、平台，没有标记（压板、目标），不是装置，也不是出入口；否则推不动。
2. 浮块上面一列一列往上数，**成摞的箱子和站着的人（不在梯子上）一起移一格**；它们要去的格也必须空着，箱子不能被带进出入口格。**沙和水不跟着走**：浮块移开后，原来压在上面的沙按格子规则落下。
3. 推成功后，推的人跟着往前走一格。
4. 推不动时浮块就是一堵墙：只能踏上去（人头顶和浮块上面一格都空时，人上一格站到浮块上），否则这一步走不了。

**撑篙**（`pole`）：人站在浮块上（脚下那格是浮块，人不在梯子上），面对挖不动的格（岩石、裂石、硬石、门，而且那一格不是浮块）用铲子（`DIG_L` / `DIG_R`）：挖不动就撑，浮块带着人往**反方向**移一格，规则同上；那边挡住就撑不动（`pole-blocked`，这一步不算）。对着能挖的土、沙用铲子仍然是挖。

**落下**：浮块永远不落；人和箱子按格子规则落下。落 3 格或以上摔伤（落在沙上不算），检查里禁止。

画法：工作台在地形里把浮块盖住的格当空，再逐格画 `left` / `mid` / `right`，刚移动的 2–3 刻用 `*_move` 帧。游戏里浮块是会移动的静态块，每移动一格重建这几格的碰撞（[DLV-02](../packages/DLV-02.md)）。

## 4 镜头

画面仍是 320 × 180：上面 20 px 是 HUD，下面 **320 × 160 是视野**，正好放下一屏 20 × 10 格。1×1 的房间不动镜头；更大的房间用跟随镜头（`CAM`、`cameraStart`、`cameraStep`，每刻调用一次，全是整数像素）：

| 参数 | 值 | 含义 |
|---|---|---|
| `viewW` × `viewH` | 320 × 160 | 视野 |
| `deadHalf` | 24 | 横向死区：人（加上前瞻）离视野中心 24 px 以内镜头不动 |
| `look` / `lookDelay` | 32 / 12 | 朝同一个方向走满 12 刻后，镜头往前看 32 px（每刻最多挪 2 px）；转身重新计数 |
| `ease` / `maxStep` | 3 / 8 | 每刻走剩余距离的 1/8（`>> 3`），至少 1 px、最多 8 px |
| `fallMargin` | 40 | 纵向只跟着"脚下的平台"：站在地上或梯子上时，人脚下的地面放在视野高度的 5/8 处；往下落时镜头不追，直到人离视野下边不到 40 px |

镜头始终夹在房间范围内。进入新房间时用 `cameraStart` 直接定位（不缓动）；房间之间仍按 v1 翻屏切换（0.3 秒）。

- **Tab 看全图**（观察模式）：游戏画面只有 320 × 180，多屏房间缩小一半显示（2×2 正好 320 × 160）。建议看全图时暂停、人不能动，再按 Tab 回到镜头（细节由 [UI-07](../packages/UI-07.md) 定）。工作台里 Tab 用来切换焦点，所以用 **V** 键切换，全图按原尺寸画（2×2 是 640 × 340）。
- **画面外的怪物**：在视野边缘离它最近的位置画一个指向它的小箭头；只提示本房间的怪物。

## 5 提示动物

每个地区一组（`worlds.json` 的 `hint_fauna`）：一只地上走的**主动物**（收零食）和一只**飞的**（只带路）。石牢 = 牢猫（主，零食是小鱼饼干）+ 蝙蝠；地府 = 小白狗（主，桂花糕）+ 彼岸蝶；其他 5 个地区各一种（[worlds.md](worlds.md) 第 2 节第 7 条）。提示动物只在配送模式出现：不占格子、不挡路，人和箱子从它身上过去；不受伤，怪物不理它；同一种动物不再当随机生态（`ambient_exclude`）。

**三级提示**：
1. **位置**：它待在下一步要用的东西旁边，远远看去就是线索。
2. **走近**：人走到 3 格以内，它看向或走到目标上，并在 `show.at` 画出 `show.dir` 方向的箭头（例如"往右推"）。
3. **零食**：对主动物用一块零食，它头顶冒出这一步的 `text` 气泡。零食是道具 `snack`（10 金币，每个驿站 3 块，一块换一句；同一个道具，石牢包装成小鱼饼干、地府是桂花糕）。喂飞的只显示目录里的 `fed` 文案（"喂零食要找猫"），不消耗零食。

**下一步是哪一步**：`nextHint(M, s)` = 第一个 `done` 谓词为假的步骤；全部为真时没有提示（动物趴下休息）。只看当前局面，所以**同样的局面总给同样的提示**；走错了（比如没倒沙就先撑过去），谓词又变假，提示自动回到那一步。

**提示步骤** `{text, target, show: {action, dir, at}, done}`：`text` 是玩家能照着做的一句话，不写坐标；`target` 是动物要去的格；`show.action` 是 `walk`、`climb`、`push`、`lever`、`dig`、`pour`、`pole` 之一。

**`done` 谓词**（坐标是房间格子，翻转时跟着翻）：

| 谓词 | 什么时候为真 |
|---|---|
| `{covers: [x, y]}`（可加 `float: 编号`） | 有浮块（指定的那块）盖住这一格 |
| `{crate: [x, y]}`（可加 `kind`） | 这一格有箱子（指定种类） |
| `{player: [x0, y0, x1, y1]}` | 人在这个矩形里 |
| `{empty: [x, y]}` / `{sand: [x, y]}` | 这一格是空的（挖开了）/ 是沙 |
| `{door: 编号}` | 这扇门开着 |
| `{lever: 编号}` | 这个拉杆拉下了 |
| `{device: 编号, value: v}` | 这个装置的状态等于 v（不写 value 时是 1：承重桥塌了、吊篮停在 1 号站，站号从 0 数） |
| `{bag_sand: n}` | 沙袋里至少 n 格沙 |
| `{all: [...]}`、`{any: [...]}`、`{not: p}` | 组合 |

**谁来提示**：`show.action` 是 `walk` / `climb`（该去哪儿）时由飞的带路——蝙蝠倒挂在目标上方的天花板，彼岸蝶停在目标上方；其余（`push`、`lever`、`dig`、`pour`、`pole`）由主动物来——猫 / 狗坐在目标旁边最近的能站的空格。只有主动物收零食。

**检查**（`hintTrace`）：按作者解（没有就用最短解）逐步回放，记下每一步 `done` 第一次为真的时刻；第 1 步一开始就为真、某一步从没完成、后一步比前一步先完成，都报错。

已知不足：工作台里动物走向目标是直线移动（会穿墙），游戏里要按格子寻路走过去（[DLV-02](../packages/DLV-02.md)）。

## 6 开局池与地图布局

开局池是 `slices.json` 的 `delivery_pool`：`pool.maps`（地图和权重：`dungeon_2`、`diyu_1` 各 1）、`pool.weights`（稀有度权重 common 4 / rare 2 / legendary 1）、`pool.rerolls`（可以重转 1 次）。

随机数和 v1 相同（xorshift32，`PB.mapgen.makeRng`，见 [delivery-maps.md](delivery-maps.md) 第 3 节）。`generate(seed, pool, maps, cat, templatesOf, picks)` 取随机数的顺序（游戏必须一致）：

1. **地图轮**：按地图权重抽一次（`pick` 无论几个选项都只取一个随机数）。
2. **收件人轮**：只在这张地图的 `recipients` 里，按稀有度抽一次。
3. **货物轮**：这张地图的 `cargo`，去掉 `cargo_only` 不给这位收件人的（`diyu_1`：纸扎小楼只给先人和黑白无常），按稀有度抽一次。
4. **房间顺序**：按地图的 `layout.sequence` 依次排角色，带 `chance` 的那项 `rng.int(100) < chance` 才加进来。
5. **起点位置**：方向 `right` 起点在第 0 列、行随机；`left` 在最后一列；`down` 在第 0 行、列随机；`up` 在最后一行。
6. **深度优先摆房间**，每一间：同角色的候选按 `weight`（默认 10）加权打乱（`weightedOrder`），用过的不再用（这个角色只有一间时除外，但不能和上一间相同）；跳过 `needs` 还没教过的、`only` 不合的；翻转先试哪边 `rng.int(2)`（`mirror: false` 只试不翻）；可用路线等权打乱。路线的入口必须接上一间的出口（对边、口位相同），出口不能朝 `FORBID_OUT`（往下的地图不朝上出、往上的不朝下、往右的不朝左、往左的不朝右），最后一间的出口是 `recipient`；放得下（不出地图、不和已放的房间重叠）就摆下一间，走不通就回溯。
7. 每次尝试最多走 20000 步，最多 24 次尝试（每次重新抽起点）；都失败就报错（检查工具会先发现）。

**重转**：滚轮停下后玩家可以重转（次数 = `rerolls`），重转后定下的结果作为 `picks = {map, recipient, cargo}` 再调一次 `generate`：三个滚轮**照样各抽一次**，只是用 `picks` 替换抽到的值，后面布局用到的随机数不会错位；`picks` 里的收件人必须在这张地图里、货物必须合 `cargo_only`，否则用抽到的。重转本身怎么抽（另一条随机数流）由 [UI-07](../packages/UI-07.md) / [DLV-02](../packages/DLV-02.md) 定，工作台用固定的随机数模拟。

**同种子同局**：同样的 `seed` 和 `picks` 一定生成同一张地图（测试检查）。

两张地图：

| 地图 | 网格（屏） | 方向 | `layout.sequence`（括号里是出现概率） |
|---|---|---|---|
| `dungeon_2` 废弃的符文监狱 | 12 × 3 | `down` | 起点、教、教、喘口气（50%）、发展、驿站、转折、发展（60%）、收件人之家 |
| `diyu_1` 地府·酆都 | 13 × 3 | `right` | 同上，收件人之家前再加喘口气（40%） |

300 个种子的统计（`pools2`）：两张图 151 / 149 局；每局 7–10 间房（7 间 35 局、8 间 138、9 间 105、10 间 22），8–15 屏。

## 7 检查工具与工作台

`node tools/check-rooms2.mjs`（`--write` 写报告；`--seeds N` 开局池种子数，默认 300；`--only <房间>` 只查一间）：

- 每间房先校验；每种翻转 × 每条路线：最短解（宽度优先，最多 250000 个状态）、作者解回放、`requires` 冻结后无解、提示顺序、怪物不进解谜区。
- 开局池：每个种子都能生成，`joints` 核对相邻房间的出入口对得上；统计地图、收件人、货物的分布，每局房间数、屏数。
- 报告 `content/rooms2-check.generated.json` 不存动作，最短解在工作台里现算（最慢约 83 ms）。房间改了没重跑，`node tools/content.mjs check` 报"过期"。
- `tests/rooms2.test.mjs`：浮块推、带人带箱、挡住推不动、撑篙反向、摔伤、同种子同局、检查失败数为 0、文字表与房间同步、画法不抛错。

工作台「配送 v2」页的参考实现在提交 `676e89e`、`34dc229`（`workbench/js/app/views/rooms2.js`）；工作台界面改版后按新样式重新接入，见 [UI-08](../packages/UI-08.md)。页面功能：

- **开局池** `#rooms2/pool[/<种子>]`：三个滚轮依次停（地图 → 收件人头像 → 货物图），重转；种子地图总览（每间房画成缩略图，按顺序编号、按角色着色），点一间跳到那间的房间页（带翻转和路线）；旁边是开局池统计。
- **房间** `#rooms2/<房间>`：整间房的画面、翻转、选路线、作者解 / 最短解逐步播放、解谜区和怪物巡逻范围、提示步骤和提示动物、检查结果；镜头视图（320 × 180，V 切全图）；回合制试玩（方向键走 / 爬，挖、倒沙，撤销，重来，H 喂零食；摔伤的一步会被拒绝）；左栏「美术候选」开关（关掉时未确认的美术画成占位）。
