# 推箱项目目标与需求记录

更新日期：2026-10-15（Asia/Shanghai）。

成品要保持当前像素美术方向和简单、易上手的操作，同时让 SDK 的元素反应、流体和刚体能力成为玩家解决问题、应对危险的核心。游戏计划包含教学、闯关、挑战三个模式；挑战模式从第一关起，每关都保持地狱难度，并使用更大的地图、陷阱和怪物。

本文作为后续补充目标的固定入口。用户已明确的目标、用户试玩反馈、参考游戏事实和设计建议分别记录。后续有新要求时更新对应条目，并在末尾保留日期与变更说明。与旧 Demo 规范冲突时，以用户最新要求为准。

## 阶段推进总路线（含阶段 1.5 美术预览与阶段 2A/2B 拆分）

> 2026-10-15 补充：以下阶段记录保留历史决策。后续重设计以 G08–G09 及 [统一设计草案](mode-and-level-design.md) 为准：实验关可重做、全程横版、主线降低难度、旧 SDK 优先并允许游戏层机关；现有 6 图 / 36 关是实验配置，不作为新设计数量硬上限。

用户已明确后续推进路线，把“需要改 C++ 引擎的扩展”排在外部试玩之后，优先基于现有引擎做出充实的 6 大地图关卡池（详见 [三大阶段开发总规划](../archive/plans/2026-10-14-three-modes-and-mechanisms.md)、[关卡池与推进设计方案](mode-and-level-design.md) 与 [美术工程化与多风格地图设计](art-architecture-and-biome-design.md)）：

1. **第一阶段（已完成验收并提交封存）**：
   - 美术全改为纯代码生成 + 主界面大厅 UI + `T01–T04` 四个简单教学关（18/18 测试脚本全部通过）。
2. **阶段 1.5（当前过渡步：美术目录模块化改造 + 六大风格大地图观察池预览）**：
   - 将 `procedural_art.gd` 拆分为 `pushbox/scripts/art/` 模块化目录，升级 `world.gdshader` 支持 6 大地图风格，并在大厅接入 6 张大地图实机视觉预览（观察池雏形）。
3. **第二阶段 A（优先执行 · 零改 C++ 引擎的可玩闯关模式）**：
   - **完全基于现有 `ele-base-cpp v1.2.0` 引擎（不改一行 C++ 源码）**，落地**地牢、森林、遗迹、洞穴、天空岛、宇宙** 6 大地图的「常规玩法 + 地图独特玩法」。
   - 建立 **6 大地图 × 每图 6 关 = 36 关有解关卡池** 与 **地图观察池（侦察预览）**，实现**「在当前地图池通关满 3 关即解锁下一张地图」**的闯关流转，并保证每关 100% 通过作者解法自动回放校验，交付给外部玩家试玩。
4. **第二阶段 B（外部玩家试玩反馈后启动 · 改 C++ SDK 引擎扩底层新特性）**：
   - 根据玩家对阶段 2A 的试玩反馈，再去 `ele-base-cpp` 仓库扩展底层 C++ 新特性（如 `EXT-03` 周期电路静止判定、`EXT-06` 流量传感器、`EXT-09` 无损唤醒、连续气压风场、方向性/温度条件反应），并补充进后续关卡池。
5. **第三阶段（最后大阶段 · 地狱挑战模式）**：
   - 将所有特性全部糅合，配合 `640×384` 多房间连通大地图、陷阱和怪物，打造地狱难度挑战模式。
