# 配送模式：实时规则（设计模型）

状态：**有效（第一个可玩切片的第 3 步，2026-10-15）**。上位设计见 [mode-delivery.md](mode-delivery.md) 第 4、5、7 节；切片范围和数值见 [delivery-slice.md](delivery-slice.md)；房间与地图见 [delivery-maps.md](delivery-maps.md)。

本文件规定配送模式一局里"世界怎么动"：刻、移动间隔、输入、下落、怪物、受伤、货物、驿站、换房间、结算。规格以代码为准，代码就是游戏移植时的规格：

| 代码 / 数据 | 内容 | 游戏里对应 |
|---|---|---|
| `workbench/js/core/realtime.js` | 本文件的全部规则（工作台和 Node 工具共用同一份） | `modes/delivery/realtime.gd`（刻循环、人物、下落、结算）+ `gameplay/entities/monster.gd`（怪物） |
| `content/catalog/slices.json` 的 `dungeon_1`，货物、收件人、怪物、道具条目的 `params` | 全部数值（数据里写秒，模型换算成刻） | 同一份数据（`generated/content/`） |
| 每个房间模板的 `demos`（第 12 节） | 演示输入：一段按键脚本和它应有的结局 | 游戏的 headless 回放测试 |
| `content/export/delivery-golden.json` 的 `replays` | 每段演示（和它的翻转）逐刻回放的记录 | 游戏必须逐项复现（第 12 节） |
| `tools/check-rooms.mjs`、`tests/realtime.test.mjs` | 跑全部演示；规则的单项测试 | — |

**这是设计模型，不是 SDK 验证。** 它证明规则自洽、每段演示能达到预期、同样的输入永远得到同样的结果；它不证明 SDK 里沙的真实表现，也不证明手感（第 13 节）。

## 1 刻与时间

- 世界按固定的**逻辑刻**推进，每秒 60 刻（`time.tick_hz`）。数据里的时间一律写秒，换算成刻 = 秒 × 60 四舍五入。画面可以按任何帧率插值，但规则只在刻上发生。
- 全部是整数运算，按固定顺序处理（第 3 节），所以同一个房间、同一段输入，结果逐刻相同。

| 项 | 秒（数据） | 刻 |
|---|---|---|
| 走一格、登一格、爬一格；撞上会伤人的怪物（原地不动） | 0.22 | 13 |
| 推箱子、推怪 | 0.30 | 18 |
| 挖、倒沙 | 0.35 | 21 |
| 和龟掌柜说话、把货交给收件人、用道具 | 0.40 | 24 |
| 走一格的动画（只是画面） | 0.10 | 6 |
| 下落一格（人、箱子、沙、怪物、收件人一样） | 每秒 12 格 | 5 |
| 受伤后的无敌时间 | 1.5 | 90 |
| 换房间（滑屏） | 0.3 | 18 |
| 鼠群：巡逻一格 / 追人一格 / 逃跑一格 | 0.3 / 0.25 / 0.2 | 18 / 15 / 12 |
| 鼠群：逃跑多久 / 被推后愣多久 / 困住多久 | 3 / 0.5 / 3 | 180 / 30 / 180 |
| 骷髅守卫：巡逻一格 / 困住多久 | 0.5 / 5 | 30 / 300 |
| 僵尸闲逛一格 | 0.8 | 48 |
| 冰淇淋化掉 1 格（在地精铁匠家里快 3 倍） | 45（15） | 2700（900） |

三个钟：

| 钟 | 什么时候走 | 用来 |
|---|---|---|
| 总刻数 | 每一刻都走（包括换房间的 18 刻） | 事件时间、回放记录、演示脚本的等待 |
| **送货用时** | 人在房间里的每一刻；换房间、暂停、打开货架时不走 | 结算的用时、冰淇淋化 |
| **房间钟**（每个房间一个） | 只在人物在这个房间里时走 | 怪物的计时状态（被推愣住、被困、逃跑）。人不在的房间整个停住，回来时从停下的地方继续 |

## 2 输入与人物的行动

- 每一刻的输入 = 正按着的方向（`held`，没有就空）+ 这一刻新按下的一个动作（`press`，没有就空）。
- **输入缓冲**：新按下的动作放进一个格子（只有一格，后按的覆盖先按的）。人物能行动的第一刻，先试缓冲里的动作，试过就清掉（成不成功都清）；缓冲是空的，就试正按着的方向。所以按住方向键会在每个间隔结束时自动走下一格；间隔里按下的键会记住一次，不会"吞键"。
- **能行动** = 间隔已经走完，而且人物没有在下落（在梯子格里，或者脚下有东西托着）。下落中不能行动，按下的动作留在缓冲里，落地后再试。
- 动作成功：开始这个动作的间隔（第 1 节）。动作失败（被挡住）：不花间隔，下一刻可以再试。

每个动作按下面的顺序判断，第一条成立就执行：

| 动作 | 判断顺序 |
|---|---|
| ← / → | ① 前面出了房间：站在这一边的出入口格上就**离开房间**，否则挡住。② 前面是箱子，箱子那边能放箱子：**推箱**，人跟进一格。③ 前面是怪物：能推、没被困、它那边能放怪物 → **推怪**（怪物移一格，愣 0.5 秒）；会伤人且没被困 → 人**受伤**、原地不动，怪物转向背对人；否则挡住。④ 前面是收件人：**送达**。⑤ 前面能走：**走**一格。⑥ 前面是实地或箱子，而人头顶和前面那格的上面都空：**登一格**。⑦ 挡住 |
| ↑ | ① 同一行、左右一格内有龟掌柜：**说话**（打开货架）。② 在梯子上、在第 0 行、这里是上边的出入口：**离开房间**。③ 在梯子上，上面一格也是梯子且能进：**爬上**一格 |
| ↓ | ① 在梯子上、在第 9 行、这里是下边的出入口：**离开房间**。② 自己在梯子上或下面一格是梯子，且下面一格能进：**爬下**一格（可以从梯子下到空地上，然后下落） |
| 挖 ← / → / ↓ | 目标格在房间里、不是出入口格、是散沙或夯土、没有被关着的门、沙袋不到 9 袋：变空，沙袋 +1 |
| 倒沙 ← / → | 沙袋至少 1 袋，目标格能放箱子（不是出入口、不是实地、没有箱子、怪物、收件人、人）：放下一格沙，沙袋 −1；沙随后按第 4 节下落 |
| 用道具 1–3 | 那一格的道具：急救包（心没满才能用，+1 颗心）、绳梯（见第 9 节）。用掉以后，后面的道具往前挪一格 |

"能走" = 在房间里、不是实地、没有箱子、怪物、收件人。门关着算实地。梯子、压板、渡门、龟掌柜都是背景，不挡人。

## 3 一刻里的顺序

1. 记下这一刻新按下的动作（进缓冲）。
2. 正在换房间：倒数一刻，结束（世界不动，送货用时不走）。
3. 总刻数、送货用时、当前房间的房间钟各走一刻；无敌时间、人物的间隔各减一刻。
4. **人物行动**（第 2 节）。如果是离开房间，这一刻到此结束，下一刻开始换房间（第 10 节）。
5. **下落**（第 4 节）。
6. **怪物**，按房间里怪物的顺序逐个行动（第 5 节）。怪物的顺序 = 摆好（翻转后）的房间地图从上到下、从左到右扫到的顺序。
7. **收件人**闲逛（第 8 节）。
8. **门**：每组压板全被压着就开，否则关；门里有人、箱子、怪物或沙时不关。压板只认人、箱子和实地（包括落在上面的沙）；怪物不踩压板。
9. **拾取**：人所在格的金币、沙袋掉落被拾起（沙袋最多 9）。
10. **货物会化**：冰淇淋的融化计数 +1（在地精铁匠家里 +3）。
11. **结局**：送到了 → 成功；否则心 ≤ 0 → 失败（心）；否则完好度 ≤ 0 → 失败（货物）。

## 4 下落

- 每个会落的东西（散沙格、箱子、怪物、收件人、人）各有一个下落计数：下面没东西托着时每刻 +1，到 5 刻往下移一格、计数归零；被托住时计数归零。所以下落 = 每 5 刻一格。
- 扫描顺序：从最下面一行往上，每行从左到右；每格里依次看散沙、箱子、怪物、收件人、人。一刻里每个东西最多落一格。
- **谁托得住谁**：

| 落下的东西 | 被这些托住 |
|---|---|
| 人 | 实地、关着的门、箱子、怪物（能站在怪物头上）、收件人；人在梯子格里不落 |
| 箱子、沙 | 实地、关着的门、出入口格、箱子、人、收件人。**怪物托不住**：箱子落进怪物的格子 = **压倒**它，沙落进怪物的格子 = **埋住**它 |
| 怪物、收件人 | 箱子、沙托得住的那些，加上怪物和梯子（怪物把梯子当实地，走在梯子顶上不会掉进去） |

- **落地**（落过至少一格后被托住时结算一次）：
  - 人：落了 3 格以上（`player.fall_hurt_rows`）、落点不是沙 → 掉 1 颗心。拿着花瓶时落了 2 格以上、落点不是沙 → 花瓶完好度 −1。
  - 箱子落在人头上 → 人受伤。箱子停在人头上，人走开后接着落。
  - 怪物落在人头上 → 人受伤。怪物落了 3 格以上（`monster_fall_ko_rows`）、落点不是沙 → **摔晕**；否则落进一格宽的坑（左右两边都是怪物的墙）→ **被困**。
- 散沙是整格的，竖直往下落，不会滑坡（与关卡模式的格子模型相同）。

## 5 怪物

### 5.1 走法

- 怪物一格一格地走：每隔"一步的刻数"走一格（追人、逃跑时用各自的刻数）。刚进房间时先等一个间隔。
- **回头**：前面一格不能进（实地、关着的门、箱子、梯子、出入口格、别的怪物、收件人、房间外），或者从前面那格往下会落 2 格以上（`cliff_rows`），或者前面那格正下方是人（**怪物不踩人的头**）→ 掉头。掉头也算走了一步。所以怪物会走下一级台阶、掉进一格深的坑，但不会自己走下高台。
- **巡逻**（骷髅守卫、鼠群平时）：一直往前走，碰到上面这些就掉头。
- **追人**（鼠群）：每一刻都看一眼：人和它在同一行、相距不超过 5 格（`sight_tiles`）、中间没有实地和箱子 → 看见了，转向人，改用追人的速度；看不见了就回到巡逻，方向不变。
- **逃跑**（鼠群偷到东西以后）：背对人跑 3 秒，用逃跑的速度；逃跑中再碰到人只会掉头。
- 怪物不爬梯子、不踩压板、不离开房间、不穿过别的怪物。

### 5.2 碰到人

怪物走下一步时，前面一格正好是人，就是**碰到人**（人走进会伤人的怪物见第 2 节）：

| 怪物 | 碰到人 |
|---|---|
| 骷髅守卫（`contact: hurt`） | 人掉 1 颗心（无敌时间里不掉），怪物掉头 |
| 鼠群（`contact: steal`） | 人有沙就偷 1 袋沙；没有沙、金币够 5 就偷 5 金币；都没有就什么也没偷到。然后逃跑 3 秒。偷走的东西在它被放倒时掉出来 |

### 5.3 推、压、埋、摔、困

| 办法 | 规则 |
|---|---|
| **推怪** | 只有能推的怪（鼠群）。人走进它的格子、它那边能放怪物 → 它移一格，**愣住** 0.5 秒（不走、不偷），人跟进一格。推下去以后照常下落 |
| **压怪** | 箱子落进怪物的格子 → 怪物被压倒 |
| **埋怪** | 沙落进怪物的格子 → 怪物被埋住。沙不能直接倒在怪物身上：要倒在它上方，让沙落下去 |
| **摔怪** | 怪物一次落了 3 格以上、落点不是沙 → 摔晕 |
| **困怪** | 怪物落进一格宽的坑（左右都是它的墙）→ 被困：不走、不伤人、不偷，人可以站在它头上。困住时间到了，它往前（不行就往后）斜着爬出坑：坑口那格和斜上方那格都能进、斜上方那格下面托得住。出不来（例如人站在它头上、坑口被填了）就再困一轮 |

被压倒、埋住、摔晕的怪物**放倒**：从房间里消失，不再出现（这一局里）；在它倒下的格子掉出金币（怪物自带的 + 它偷走的）和偷走的沙。那一格已经被箱子或沙占了，就掉在往上第一个空格。

### 5.4 计时状态

愣住、被困、逃跑都记"到房间钟第几刻结束"。房间钟只在人物在这个房间时走（第 1 节），所以离开房间时被困的怪物，回来时还是被困，剩下的时间不变；"重来这个房间"连房间钟一起回到进门时。

## 6 人物：心、受伤、无敌

- 3 颗心（`player.hearts`）。受伤：怪物碰到、走进会伤人的怪物、箱子或怪物落在头上、摔 3 格以上（落点不是沙）。
- 每次受伤掉 1 颗心，然后无敌 1.5 秒（这段时间里不再掉心）。心掉到 0 → 这一单失败。
- 拿着花瓶时，每次受伤花瓶完好度也 −1（`hurt_damage`）。

## 7 货物

完好度上限 3（`cargo_integrity`）。完好度 = 3 − 损伤 − 化掉的格数，归零 → 失败。

| 货物 | 规则（`cargo.json` 的 `params`） |
|---|---|
| 信件 | 石牢里没有规则（`water_damage` 留到有水的地区） |
| 花瓶 | 一次落 2 格以上、落点不是沙 → −1（`fragile_fall_rows`、`sand_cushion`）；人受伤 → −1（`hurt_damage`） |
| 冰淇淋 | 融化计数每刻 +1，在地精铁匠家里每刻 +3（`home_melt_mult`）；化掉的格数 = 计数 ÷ 2700 向下取整（`melt_secs_per_point` 45 秒） |

## 8 收件人与送达

- 收件人是一个"身体"：挡人（走进他的格子 = 送达）、托得住人、挡箱子和沙，怪物把他当墙。
- 老矿工、地精铁匠站着不动；僵尸闲逛：和巡逻一样走（0.8 秒一格），碰到墙、2 格以上的落差、人的头顶就掉头。他一开始朝房间中间走（翻转后也一样）。
- **送达**：人走进收件人的格子，或者闲逛的收件人下一步正好走到人的格子。送达在这一刻的最后结算，比失败优先。
- 地精铁匠的家很烫：在他家里冰淇淋化得快 3 倍（只有铁匠是这一单的收件人时）。

## 9 驿站与道具

- 龟掌柜是背景，不挡人也托不住人。站在他旁边（同一行、左右一格内）按 ↑ = 说话：**打开货架**（游戏里打开货架时世界暂停）；每个驿站**回 1 颗心一次**——第一次在心没满时说话时回，满心时说话不会用掉这一次。
- 货架（`slices.json` 的 `station`）：说过话才能买；每样东西有库存（每个驿站各自一份）；金币要够。沙袋 10 金币，直接加 1 袋沙（满 9 袋不能买）；急救包 50、绳梯 25，各占一个背包格（3 格，满了不能买）。
- 绳梯：挂在人面前那一列，从人所在的那一行往下，最多 6 格（`max_tiles`），遇到放不了箱子的格就停；面前那格放不了就用不了。挂好的绳梯就是梯子，留在这个房间里。
- 急救包：心没满时 +1 颗心。

## 10 房间、换房间、重来这个房间

- 渡门房间：人从渡门的格子出发，面朝右。
- **离开房间**：站在出入口格上往外走（左右出入口按 ← / →，上下竖井在最上 / 最下一格按 ↑ / ↓）。地图上那个方向的房间第一次进入时按模板新建，以后进入时就是离开时的样子。人进入新房间对应的格子：从左边离开 → 新房间第 19 列，从右边 → 第 0 列，行不变；从上边 → 第 9 行，从下边 → 第 0 行，列不变。朝向不变。
- 离开的房间停住（第 1 节的房间钟）：怪物不走，沙不落，箱子停在半空也会停住。
- 换房间时有 18 刻滑屏，期间世界不动，送货用时不走，按下的键进缓冲。
- **重来这个房间**（暂停菜单；工作台按 R）：房间回到这次进门时的样子（地形、门、箱子、正在落的沙、绳梯、怪物、掉落物、龟掌柜的库存和说话状态、收件人、人、房间钟），人物状态也回到进门时（心、金币、沙袋、道具、货物损伤）；**送货用时和冰淇淋的融化不倒回**。缓冲清空。

## 11 结算（整数运算）

参考时间 = 主路径上每一间要走的那条路线的参考用时之和（[delivery-maps.md](delivery-maps.md) 第 4 节），换成刻；用时 = 送货用时（刻）。全部按整数算，任何移植都得到同样的数：

```
用时% = 用时 ≤ 参考 ? 150 : max(50, 150 − floor(100 × (用时 − 参考) ÷ 参考))
喜欢% = 收件人喜欢这件货物 ? 150 : 100
小费  = floor((报酬 × 剩余完好度 × 用时% × 喜欢% + 分母 ÷ 2) ÷ 分母)，分母 = 完好度上限 × 10000
评分  = floor(剩余完好度 × 用时% ÷ 完好度上限)；≥ 140 为 S，≥ 100 为 A，≥ 60 为 B，其余 C
带回  = 成功 ? 拾到的金币 + 小费 : floor(拾到的金币 × 50 ÷ 100)（失败没有小费，没有评级）
```

（就是 [delivery-slice.md](delivery-slice.md) 第 10 节的公式：小费 = 报酬 × 完好度系数 × 用时系数 × 喜欢系数，四舍五入。）

## 12 演示输入与回放记录

### 12.1 模板里的 `demos`

每个房间模板带一段或几段演示，说明这一间想让玩家怎么玩，同时是实时规则的验收用例：

```json
{"id": "crush", "name": "压怪：等骷髅走到台下，把箱子推下去",
 "mechanisms": ["crush_monster", "push", "ladder"],
 "open": {"left": "low", "right": "low"}, "from": "left.low",
 "script": ["R*3", "U*3", "R", "R*4", "wait 205", "R", "R", "R*10"],
 "expect": {"end": "exit:right", "hearts": 3, "kos": 1, "ko": ["crushed"], "coins": 20, "cargo": 3}}
```

| 字段 | 说明 |
|---|---|
| `open`、`from` | 打开哪些出入口；人从哪里进来（`gate` 或 `边.口位`） |
| `script` | 按键脚本（12.2） |
| `expect` | 应有的结果：`end`（`exit:<边>`、`deliver`、`fail:hearts`、`fail:cargo`），以及结束时的 `hearts`、`coins`、`sand`、`kos`（放倒几只）、`cargo`（完好度）、`ko`（必须出现的放倒方式：`crushed` 压、`buried` 埋、`fall` 摔）、`events`（必须出现的事件，如 `trap`、`talk`、`door-open`） |
| `cargo`、`recipient` | 这一段用哪件货、哪位收件人（默认切片的第一件货；收件人之家默认第一位收件人） |
| `run` | 进门时的人物状态（`hearts`、`coins`、`sand`、`items`），例如驿站演示从 2 颗心开始 |
| `mechanisms` | 这一段演示了哪些机制；只属于配送模式的机制（推怪、压怪、困怪）的状态由这些演示算出 |
| `limit` | 最多跑多少刻（默认 5400 = 90 秒） |

模板能翻转的，每段演示还会**翻转着再跑一遍**：出入口、起点、脚本里的左右、预期的出口都一起翻。

### 12.2 按键脚本

| 写法 | 意思 |
|---|---|
| `R`、`L`、`U`、`D`、`DIG_L` / `DIG_R` / `DIG_D`、`POUR_L` / `POUR_R`、`USE_1`… | 按一下这个动作 |
| `R*4` | 按 4 次 |
| `wait 205` | 等 205 刻 |
| `hold R 40` | 按住 → 40 刻 |

脚本像一个会提前按键的玩家：缓冲空了就按下一个动作（动作在人物能行动的那一刻执行）。脚本按完后再走 30 刻让世界停下，然后停止；送达、失败或离开房间时提前停止。

### 12.3 回放记录（`delivery-golden.json` 的 `replays`）

`node tools/check-rooms.mjs --write` 把每段演示（和它的翻转）的结果写进 `replays`：模板、演示、是否翻转、摆法、起点、货物、收件人、进门状态、（已翻转的）脚本、结局、总刻数，以及**每 30 刻一帧和最后一帧**：

```
{"t": 刻, "p": [人 x, y], "hearts": 心, "coins": 金币, "sand": 沙袋, "cargo": 完好度,
 "m": [[怪物 x, y, 状态首字母] 或 null（已放倒）, ...], "c": [[箱子 x, y], ...]}
```

状态首字母：`w` 巡逻、`c` 追人、`f` 逃跑、`s` 被推愣住、`t` 被困。`events` 列出主要事件和它们发生的刻（不含走、爬、登、落地），用来对照出错的位置。

**游戏必须复现**：同样的摆法、起点、货物、收件人、进门状态和脚本，得到同样的每一帧和同样的结局（例外见第 13 节的沙）。

## 13 和关卡模式、SDK 的关系

- **与关卡模式相同的规则**：推箱、登一格、梯子、挖、倒沙、压板与门、箱子下落，与关卡模式的格子模型（[game-design.md](game-design.md) 第 4 节、`tilemodel.js`）一致。`tests/realtime.test.mjs` 实测：让实时规则一步一步走完 M01–M07 的作者解，每步等世界停下，最后的人、箱子、地形、沙袋与格子模型逐格相同。
- **只有实时才有的**：摔落伤害、受伤与无敌、箱子砸人、怪物、货物损伤、没有撤销（改为"重来这个房间"）。推怪、压怪、困怪没有回合制版本，所以不进关卡模式验证，改由每个模板的演示验证（机制的状态由演示算出）。
- **SDK 里的沙**：模型里一袋沙是整格、每 5 刻落一格。SDK 里一袋沙是 256 个 sand cell，由求解器落下，可能摊开、速度也不同。游戏层按格判断时，沿用关卡模式的阈值：**一格里的 sand cell ≥ 128 就算这一格是沙**（能站、能挖、摔下来算软着陆、压着压板）；**怪物所在格里的 sand cell 达到 128 就算被埋**。人、收件人挡沙（沙停在他们头上），怪物不挡沙。出入口格对沙和箱子是墙。
  - 【待验证】开发方在配送样板里实测：一袋沙倒进一格宽的坑、倒在被困怪物的上方时，多少刻达到阈值。涉及落沙的演示（守卫廊·困怪、鼠洞·挖）允许"被埋"的那一刻和回放记录有出入，但结局和 `expect` 必须一致；差异写进验证报告，由设计负责人调整模型（例如下落速度）后重新生成回放记录。其余演示必须逐帧一致。
- 游戏实现和本规格不同时，以 SDK 实测为准、记录差异，交设计负责人改规格；不要只改游戏（[architecture.md](architecture.md) 第 7 节）。

## 14 模型里没有的

- 水、火、气体、碎石（切片地区没有；以后的地区加入时再扩展模型）。
- 怪物寻路、爬梯子、飞行、成群行动；怪物偷货物本身。
- 画面与手感：走路动画、受伤闪烁、镜头、音效；"0.22 秒一格"对不对，要在 Godot 里试玩判断。
- 暂停菜单、滚轮、结算界面的操作流程（在切片文档里，不影响规则）。
- 帧耗时（开发方在样板里测）。

## 15 工作台

「地图预览」页的每个房间（地图里的一间或模板页）上方有一排按钮：**静态**（地形与检查路线）、**演示**（选一段演示，按脚本自动播放）、**试玩这一间**、**试玩整张图**（从渡门走到收件人，自动换房间，路过驿站可以打开货架）。可以选货物和收件人、播放速度 ×1 / ×2 / ×4；右栏实时显示时间、心、金币、沙袋、完好度、道具、最近的事件，送达或失败时显示结算算式。键盘：方向键或 WASD 走 / 爬，Shift + 方向挖，Ctrl + 方向倒沙，↑ 和龟掌柜说话，1–3 用道具，R 重来这个房间。怪物、收件人、龟掌柜、渡门、金币和 HUD 目前是**占位**，美术在第 4 步。
