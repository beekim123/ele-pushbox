第 2 步（[delivery-maps.md](design/delivery-maps.md)）：

- **房间模板格式** `pushbox.room/1`（`content/rooms/<地区>/`）：20 × 10 格，关卡图例 + `$` 金币 + 数字图例（怪物、渡门、收件人、龟掌柜）；左右出入口是两格高的开口（口位 `low` / `high`），上下是两格宽的双梯子竖井（`mid`）；可以左右翻转，用不到的出入口封上（`caps` 写怎么封得自然），单向房间写 `routes`。出入口格对箱子、沙、怪物都是墙。
- **石牢 10 个模板**：渡门、收件人之家、驿站，以及石廊（推怪）、守卫廊（压怪 / 困怪）、鼠洞（挖穿土丘）、机关门（推箱进压板坑，单向）、竖井、转角、废井。
- **地图生成器**（`workbench/js/core/mapgen.js`）：xorshift32 整数随机数 + Spelunky 式蛇形主路径（一半从上往下、一半从下往上）+ 深度优先挑模板和口位；同一种子同一张图，取随机数的顺序写进规格，前 30 个种子的结果存成对照表 `content/export/delivery-golden.json` 给游戏比对。
- **可通性检查** `node tools/check-rooms.mjs --write`：每个模板的每一种摆法（翻转 × 打开哪几个出入口）都在关卡模式的格子模型里走一遍（沙袋 0、不用道具、没有怪物、不许摔 3 格以上），再按切片生成 300 个种子逐间核对；同时算出每条路线的参考用时。模板改了没重跑，`content.mjs check` 报错。
- **工作台「地图预览」页**：按种子（上一个 / 下一个 / 随机）看整张地图总览，点一间用已确认的石牢主题画出来并标出检查到的路线；模板页列出全部摆法和路线。怪物、渡门、收件人、龟掌柜、金币目前是**字母方块占位**，第 4 步画美术。配送模式里石牢的小老鼠生态关掉（`ambient_exclude`），免得和怪物混淆。

## 未验证 / 尚缺

- 配送切片：实时规则的设计模型与回放（第 3 步）、美术候选（第 4 步）还没做。切片里的数值是初稿，要等第 3 步用模型回放后再调。
- 地图检查只用格子模型：证明了"不靠道具、不摔伤也走得通"，**没有**证明怪物不会把路堵死、时间够不够——这要第 3 步给每个模板写演示输入，用实时模型回放。
- 参考用时（平均 34 秒）只算走路，偏短；冰淇淋"每 80 秒化 1 格"多半太宽松，第 3 步按演示回放的真实用时再定。
- 竖井、转角、废井三种能上下连的模板在大多数地图里都会出现（每张图都要上下转两次），以后可以多做几种能上下连的模板。
- 推怪、压怪、困怪没有回合制版本，不能按 game-design.md 6.7 进关卡模式验证；切片里改为在配送模式的试验房间里验证（第 3 步定具体做法）。
- 没有运行 Godot 与 SDK（本环境是 Linux，SDK 只有 macOS arm64 版本）。
- 关卡模式的水是设计模型里的**整格近似**，不等于 SDK 结果（各关 `checks` 和交接文档 5b 节）。
- 第 3–5 组只有概念卡；其中的新机关还没写进设计模型。
- 名称没有查商标；新手试玩未进行。
