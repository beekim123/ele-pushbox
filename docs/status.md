第 3 步（[delivery-realtime.md](design/delivery-realtime.md)）：

- **实时规则写进设计模型** `workbench/js/core/realtime.js`（工作台和 Node 工具共用，就是游戏移植的规格）：每秒 60 个逻辑刻、全整数、固定处理顺序；移动间隔（走 13 刻、推 18、挖 / 倒 21、说话 / 用道具 24）与一格的输入缓冲；人、箱子、沙、怪物每 5 刻落一格，摔 3 格掉心、花瓶 2 格裂；怪物巡逻、鼠群看见人就追、偷沙或金币后逃跑；推怪（愣 0.5 秒）、压怪（箱子落进它的格子）、埋怪（沙落进它的格子）、摔怪（3 格）、困怪（一格宽的坑，到时间斜着爬出来）；受伤与 1.5 秒无敌；货物规则（花瓶、冰淇淋、铁匠家 3 倍融化）；收件人（僵尸闲逛，碰到即送达）；龟掌柜说话开货架、每站回一颗心一次、库存与背包格；换房间（离开的房间整个停住，房间有自己的钟）、"重来这个房间"（时间不倒流）；整数结算（小费、评级、失败带回一半）。
- **每个模板都有演示输入**（共 15 段，能翻转的再翻转跑一遍，共 28 次回放）：渡门走出、交给老矿工、追上僵尸、铁匠家化冰淇淋、驿站回心、石廊推怪摔晕、守卫廊压怪 / 花瓶落 2 格裂 / 挖坑困住再埋、鼠洞挖穿并埋鼠、机关门推箱开门、竖井、转角、废井绕开骷髅。`node tools/check-rooms.mjs --write` 把它们全部跑一遍，结果进检查报告，**逐刻记录**（每 30 刻一帧）写进 `content/export/delivery-golden.json` 的 `replays`，游戏必须逐帧复现。演示没达到预期，内容检查报错。
- **只属于配送模式的机制**（推怪、压怪、困怪）的状态由这些演示算出，现在是"有规格"（`specified`）；要到 Godot 回放通过才算验证。
- **工作台「地图预览」能播放**：每个房间上方可以切换"静态 / 演示 / 试玩这一间 / 试玩整张图"，选货物和收件人、×1 / ×2 / ×4；右栏实时显示时间、心、金币、沙袋、完好度、道具、最近的事件，送达或失败时显示结算算式；试玩整张图会自动换房间，路过驿站能打开货架买东西；R 重来这个房间。怪物、收件人、龟掌柜、渡门、金币、HUD 仍是**占位**。
- **第 3 步里定下 / 改动的规则**（同步进 [delivery-slice.md](design/delivery-slice.md)）：冰淇淋改为 45 秒化 1 格（原 80 秒；地图参考用时平均 34 秒，80 秒几乎化不掉）；怪物把梯子当墙（也能走在梯子顶上）、不踩人的头；龟掌柜站在背景里不挡路，收件人是挡路的身体；被困的怪物不伤人，人站在它头上时它爬不出来；驿站的回心满血时不会用掉；人不在的房间整个停住（怪物的计时也停）。

第 2 步（[delivery-maps.md](design/delivery-maps.md)）：

- **房间模板格式** `pushbox.room/1`（`content/rooms/<地区>/`）：20 × 10 格，关卡图例 + `$` 金币 + 数字图例（怪物、渡门、收件人、龟掌柜）；左右出入口是两格高的开口（口位 `low` / `high`），上下是两格宽的双梯子竖井（`mid`）；可以左右翻转，用不到的出入口封上（`caps` 写怎么封得自然），单向房间写 `routes`。出入口格对箱子、沙、怪物都是墙。
- **石牢 10 个模板**：渡门、收件人之家、驿站，以及石廊（推怪）、守卫廊（压怪 / 困怪）、鼠洞（挖穿土丘）、机关门（推箱进压板坑，单向）、竖井、转角、废井。
- **地图生成器**（`workbench/js/core/mapgen.js`）：xorshift32 整数随机数 + Spelunky 式蛇形主路径（一半从上往下、一半从下往上）+ 深度优先挑模板和口位；同一种子同一张图，取随机数的顺序写进规格，前 30 个种子的结果存成对照表 `content/export/delivery-golden.json` 给游戏比对。
- **可通性检查** `node tools/check-rooms.mjs --write`：每个模板的每一种摆法（翻转 × 打开哪几个出入口）都在关卡模式的格子模型里走一遍（沙袋 0、不用道具、没有怪物、不许摔 3 格以上），再按切片生成 300 个种子逐间核对；同时算出每条路线的参考用时。模板改了没重跑，`content.mjs check` 报错。
- **工作台「地图预览」页**：按种子（上一个 / 下一个 / 随机）看整张地图总览，点一间用已确认的石牢主题画出来并标出检查到的路线；模板页列出全部摆法和路线。配送模式里石牢的小老鼠生态关掉（`ambient_exclude`），免得和怪物混淆。

## 未验证 / 尚缺

- 配送切片的美术候选（第 4 步）还没画：怪物、收件人、龟掌柜、渡门、金币、HUD、滚轮 / 驿站 / 结算界面在工作台里都是字母方块或文字占位。
- 实时规则只在设计模型里跑过，**没有在 Godot / SDK 里跑过**（本环境是 Linux，SDK 只有 macOS arm64 版本）。SDK 里一袋沙是 256 个 cell，落速和摊开方式与模型的整格沙不同：涉及落沙的两段演示（守卫廊·困怪、鼠洞·挖）的"被埋"时刻可能对不上，规格里写了按 128 cell 阈值判断、差异记进验证报告再调模型（[delivery-realtime.md](design/delivery-realtime.md) 第 13 节）。
- 手感没有人试过："0.22 秒一格"、鼠群追人 0.25 秒一格（比人略慢）、骷髅 0.5 秒一格，都只是初稿。
- 参考用时只算走路：要对付怪物的房间，演示实际用时比参考用时长（守卫廊压怪 8.3 秒、挖坑困怪 20.2 秒、石廊推怪 10.9 秒，对应路线的参考用时约 6.5 秒），S 评级可能偏难，等试玩再调 `tip` / `rating`。
- 没有"整张图从渡门到收件人"的自动回放：只有逐间的演示，加上浏览器里手动试玩整张图（换房间、驿站、结算都走得到）。
- 怪物行为很简单：只在同一行看见人、不寻路、不爬梯子；以后的地区需要飞行、守门等走法时再扩展模型。
- 竖井、转角、废井三种能上下连的模板在大多数地图里都会出现，以后可以多做几种能上下连的模板。
- 关卡模式的水是设计模型里的**整格近似**，不等于 SDK 结果（各关 `checks` 和交接文档 5b 节）。
- 第 3–5 组只有概念卡；其中的新机关还没写进设计模型。
- 名称没有查商标；新手试玩未进行。
