# 推箱项目目标与需求记录

更新日期：2026-10-14（Asia/Shanghai）。

成品要保持当前像素美术方向和简单、易上手的操作，同时让 SDK 的元素反应、流体和刚体能力成为玩家解决问题、应对危险的核心。游戏计划包含教学、闯关、挑战三个模式；挑战模式从第一关起，每关都保持地狱难度，并使用更大的地图、陷阱和怪物。

## 成品的核心玩法目标

| 编号 | 已明确的目标 | 成品应体现的效果 |
|---|---|---|
| G03 | 合理利用 SDK 底层机制。 | 玩家观察世界状态、改变环境并利用结果完成目标；SDK 机制实际参与解法。 |
| G04 | 增加各种元素反应。 | 不同材料或元素之间的反应会改变局面，产生可学习、可利用的因果关系。具体材料组合后续逐项设计。 |

当前五关 Demo 主要展示沙、水、爆破以及游戏层的箱子和机关规则，还不足以代表成品要求的机制广度与深度。

## 三个游戏模式

三种模式共享简单、易上手的操作。其区别在于学习目标、机制组合、地图规模和难度定位。

| 模式 | 用户已明确的定位 | 内容要求 | 难度要求 |
|---|---|---|---|
| 教学模式 | 简单演示各种机制的操作。 | 让玩家看见怎么操作、发生了什么、这个机制能做什么。覆盖成品实际使用的主要机制。 | 以理解和掌握操作为目的。 |
| 闯关模式 | 普通的增量式关卡，逐级增加难度。 | 从基础使用逐渐进入机制组合；后续关卡建立在已学内容上。 | 随关卡推进逐步提高。 |
| 挑战模式 | 从第一关起就是地狱难度，每一关都非常难、有挑战性。 | 地图要大，增加各种挑战、陷阱、怪物等内容，充分利用 SDK 交互。 | 第一关即极高难度，后续每关保持这一定位。 |

### 教学模式的设计建议

每个教学场景优先讲清一个机制，再给玩家一次亲手验证的机会。例如展示流体如何改道，再让玩家用同样的操作改变流向。具体教学顺序与机制清单后续确定。

### 闯关模式的设计建议

通过组合已有机制、调整资源与操作顺序逐步提高难度。新增机制应先让玩家理解，再与其他机制组合。正式关卡数量、章节结构和解锁方式后续确定。

### 挑战模式的设计建议

极高难度可以来自较长的因果链、多种危险互相影响、资源取舍和路线选择。大地图可以由相互连通的局部难题组成，陷阱和怪物也可以参与环境交互。危险的识别方式、失败反馈与重试成本应一起设计，让玩家能从失败中学到东西。

以上是设计建议。生命、战斗方式、检查点、撤销限制、随机地图、计时和排名等内容尚未确定。

## 参考游戏与可借鉴的做法

### Noita

官方介绍确认水、气体、沙和刚体参与模拟，并包含简化的材料反应、电和热力学；玩家可以燃烧、融化、冻结和蒸发环境。[官方介绍与 FAQ](https://www.noitagame.com/)

可借鉴：让材料与物理交互本身成为解法。教学演示单个稳定关系，闯关组合已学关系，挑战让多种交互同时影响局面。具体反应先对照本项目 SDK 能力核实。

### Spelunky 2

开发者介绍包含分支路线、多层关卡、怪物、陷阱与物品之间的交互，以及能流动、倾倒并改变场地的水和熔岩；基地提供安全练习。[开发者游戏介绍](https://store.steampowered.com/app/418530/Spelunky_2/?l=english)

可借鉴：通过空间结构和对象之间的关系增加挑战。怪物和陷阱除了造成危险，也可以成为触发机关、改变环境的条件。大地图应有路线与局部目标，避免单纯拉长行走距离。

### Baba Is You

官方介绍将规则作为世界中的可操作对象，玩家通过移动这些对象改变规则并产生新的交互。[官方介绍](https://www.hempuli.com/baba/)

可借鉴：用少量直观操作承载深入的机制推理，把挑战放在观察、组合与顺序上。这是对简单输入与组合深度的借鉴；本项目尚未确定引入移动文字修改规则的玩法。

### Celeste

开发者介绍强调跳跃、冲刺、攀爬等简单操作具有深入的掌握空间，同时提供极高难度章节和迅速重生。[开发者游戏介绍](https://store.steampowered.com/app/504230/Celeste/)

可借鉴：挑战可以很难，同时让失败后重新尝试的过程流畅。这里借鉴操作表达和重试节奏；本项目是否采用死亡、局部重试或整关重置，需要结合游戏节奏确定。

## 成品与当前 Demo 的技术边界

当前 Demo 使用五关列表、20×11 格地图上限和单屏画面。这些是当前实现的限制。**挑战模式的大地图已经是用户明确目标**，后续需要设计地图加载、镜头、屏幕适配和大范围模拟策略。

元素反应、流体和刚体应先核对 SDK 已有能力，再判断是否需要扩展 SDK。新增游戏规则通常可以在游戏层实现；缺失的底层模拟行为才进入 SDK 扩展评估。

当前网格箱子的移动、支撑和上浮主要由游戏层规则控制。SDK 物理刚体是另一类对象，不能直接把现有箱子当作刚体接入。成品使用刚体时，需要一起评估回合制、实时或混合推进方式，以及撤销、预演、存档和回放的兼容性。已有能力与限制见 [SDK 能力清单](sdk-capability-map.md)。

## 后续需要细化的决策

以下内容尚未确定，可在后续讨论中补充：

1. 成品继续回合制，还是采用实时或混合方式；怪物和刚体如何随玩家操作推进。
2. 第一批进入成品的元素与反应，以及它们对应的教学顺序。
3. 挑战模式大地图的尺寸、镜头方式和区域连接方式。
4. 怪物、陷阱的行为，失败条件，以及重试、撤销和检查点规则。
5. 三模式各自的关卡数量、关卡是否固定、解锁关系和进度保存方式。
6. 屏幕适配的期望，包括不同宽高比下的可见范围、像素清晰度与界面布局。
