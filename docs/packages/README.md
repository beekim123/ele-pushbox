## 模板

```markdown
# <编号> <一句话标题>

状态：待做 / 进行中 / 已交回 / 已合并 / 退回（原因）
基线：`<基线分支>` → 分支：`<前缀小写>/<编号>`（写实际的基线，不写"默认"）

**开工**（照抄）：
```bash
git fetch origin
git checkout -b <前缀小写>/<编号> origin/<基线分支>
```
**交回**（二选一）：
- 能推送：`git push -u origin <前缀小写>/<编号>`
- 不能推送：`git bundle create <编号>.bundle origin/<基线分支>..<前缀小写>/<编号>`，把 `<编号>.bundle` 交给用户

只往 `<前缀小写>/<编号>` 提交；不往 `<基线分支>`、`main` 或别的分支推送，也不合并别的分支。

设计依据：<设计文档与章节>
会碰的共享文件：<process.md 第 5 节里的哪些；没有写"无">
允许换版本的美术：<资产编号；没有写"无（art.mjs build 必须 0 bumped）">
预留编号：<只有设计包写：可以用来拆新包的编号>

## 目标
做完以后能看到、能验证的结果，一两句话。

## 要读的文件
- AGENTS.md、docs/process.md
- ...

## 可改的文件
- ...（清单之外一律不改）

## 不能碰的文件
- AGENTS.md 2a 的冻结区（除非这里明确写了允许改哪个文件）
- `docs/status.md`
- ...

## 验收标准
- process.md 第 6 节的全套检查
- 本包专门的命令：`...` → 预期：...
- 画面 / 行为：...

## 交付（制作方填写）
- 分支名、最后提交号、交回方式（推送 / bundle 文件名）
- 验收命令的实际结果
- `git diff --stat origin/<基线>..<分支>`
- 改了哪条测试的预期、为什么
- 问题：拿不准、需要用户决定的事
```
