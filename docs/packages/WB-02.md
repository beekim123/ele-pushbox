## 要做的事

1. 按 audio.md 第 4 节实现 `tools/audio.mjs` 与独立合成库 `tools/lib/audio.mjs`。支持 build / verify / approve、`--root` 隔离目录、build/verify 的 `--kind sfx|music`、build 的 `--baseline-ref <Git引用>`、verify 的 `--require-sources`。音效 events 和音乐 notes 使用同一个确定性 PCM 渲染器；WAV 无时间戳，随机噪声固定 seed。全部字段、范围、指标错误给出 uid 与字段路径。
2. build 初次音源生成 v1，同一内容重建 0 bumped/0 changed；hash 包含源中所有影响声音的数据与渲染器。按 audio.md 第 4.2 节支持锁定 Git 发布基线：新音源多次改源始终 v1，已发布音源多次改源始终基线+1，不覆盖已确认同版本不同 hash；过期/不存在基线必须失败。保存当前 preview、manifest、工作台 audio.js；`--kind` 不修改另一类的源版本或移除其导出。没有源文件允许 build 干净完成、清楚列出未制作项，不能生成假静音候选。按规范创建空 audio/approvals.json（records:[]），仅首次不存在时创建；已有记录不得清空或重排。
3. verify 检查 RMS/峰值/包络/频率/声部/噪声比例/DC/循环接缝，逐字节验证可重建性；music 的 3 秒窗和静音段检查不能漏。`--require-sources` 使缺项失败；不加时缺项标未制作，不与指标已通过混淆。
4. approve 接口、请求/记录格式、历史快照和不可覆盖的确认 WAV 按 audio.md 第 4.3 节；新 items 拒绝陈旧源、错 current 版本/hash/媒体或验证失败；独立 selections 可采用有效历史批准版本，不要求与 current 相同，拒绝历史媒体损坏或非本曲组选择。资源质量确认和曲组采用是两份事实；批准不自动选曲，草选不自动批准；后续质量确认不清空历史采用绑定，音效取该 uid 最后一条有效质量确认版本。先校验全部请求再原子写入，不留下半条记录。这个包只能在测试临时目录调用 approve，不得往仓库真的审批表加记录。
5. `tools/content.mjs` 认识 audio.json 的 entries/music_sets/policy/routes，验证本地号与 uid、重复项、每组至少三候选、曲组候选归属、默认曲组、slice/world/chapter/group 引用和回退终点。章节来自既有 groups.theme 与 level.chapter，不新增 chapter 空间。当前工具忽略 audio.json，必须补上真实断言与负例测试。`pending_references` 仅用于诊断；jeju_1 缺失时报错并交回问题，不改 slices/worlds。**派前若 jeju_1 仍缺，Claude 先完成 DSN-01 的合并再派。** 缺音源在尚未制作阶段可显示未制作，不应把整个内容目录当成损坏。
6. `tools/lib/ids.mjs` 加 sfx/music 域，分别登记音效、候选和曲组别名；遵守 sfx:push、music:dungeon_a、music:dungeon 的 uid 和规定路径。工作台映射区分 planned/missing/review/approved 的可用性，这些状态由数据推导；未确认项不能声明为可导入游戏。本包只准备 manifest/id-map 契约，不改 game/** 的导入器。
7. 在 nav 末尾追加独立声音分类，网址为 `#audio/sfx`、`#audio/music`、`#audio/maps`。页面、单一试听流、音量、循环接缝试听、缺源/缺已确认默认曲、候选并排、草选与确认请求的行为严格按 audio.md 第 5 节。按地图页动态展示已存在切片并显示规划中的 jeju_1；以实际 approved selection 计算“现在用哪首”，不从 localStorage 的草选读取采用状态。
8. 音乐/音效滑块对应已有设置语义；master 仅工作台监听增益，不写游戏存档。数据加载使用生成的 audio.js，兼容 file://；不依赖 fetch 本地文件、在线服务或 Web 服务器。音频必须明确点击播放后激活，离开声音页停止并释放。

## 验收标准

### 声音专门验收

```bash
node tools/audio.mjs build
node tools/audio.mjs verify
node --test --test-concurrency=1 tests/audio-pipeline.test.mjs tests/audio-content.test.mjs
```

预期：空源状态 build 0 错误，列出 32 音效+9 候选未制作、3 曲组未选定；verify 结构通过但明确无音源指标结果。隔离测试必须证明：

- 临时 root 的音效与 32 小节音乐重建两次 WAV SHA-256 相同；传 baseline-ref 后连续三次修改参数仍仅为基线+1（新源恒 v1），同输入第二次 build 0 bumped/0 changed；过期或不存在引用失败；`--kind` 不改另一类；换渲染器改变声音 hash。
- 高峰值/RMS不合格/频率越界/坏接缝/长静音/非法字段被拒绝；`--require-sources` 缺项失败；音效不能靠前后静音通过响度指标。
- 错 hash/版本、源改未 build、错组选择、重复请求、失败请求的原子性；音源批准与曲组采用分离；新未确认版仍保留旧确认媒体和旧采用关系；current v2 时独立 selection 能显式采用已批准 v1，历史文件损坏则失败。
- 未采用地府回退石牢，石牢也未确认就静音；地狱模式不误映射地府；未知地图与相同曲跨场景不重启。此处验证的是路由数据/工作台模型，不能宣称游戏已接通。
- 全局音效上限/限频/优先级、淡出释放占位、滚轮上限、音乐交叉淡化≤2流、离页释放、音量0保持静音。可在隔离浏览器中监听 AudioNode 调用和播放状态；测试不写真确认表。

打开 `workbench/index.html#audio/sfx`、`#audio/music`、`#audio/maps`：分类位于原菜单之后；未制作项与未选定/静音明确；临时测试数据可播放/暂停/从头/循环，候选并排，草选刷新保留但批准状态不变；控制台无错误。e2e 使用临时 root 的工作台副本与音源，不往真仓库灌测试数据。

### 全套回归（全部执行，不得只跑声音）

先检查本机其他会话的计算进程，所有命令顺序跑；设置 `OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 VECLIB_MAXIMUM_THREADS=1`。测试加 `--test-concurrency=1`，覆盖的仍是全部 `tests/*.test.mjs`；全机最多 2 个耗资源任务/计算 worker，不因测试文件多而增加并发。

```bash
node tools/content.mjs check
node tools/check-levels.mjs
node tools/check-rooms.mjs
node tools/check-rooms2.mjs
node tools/art.mjs build
node tools/art.mjs verify
node --test --test-concurrency=1 tests/*.test.mjs
node tests/workbench.e2e.cjs
```

预期：content 0 error；三个设计模型检查全部通过（不等于 SDK 验证）；art build **0 bumped**，`art/approvals.json` 记录数量和字节不变；art verify ok；单元测试和工作台 e2e 全部通过。运行前后核对冻结区和美术版本，不得把意外换版本提交。如果已有包外失败，保留结果、在「交付 · 问题」写明命令、实际错误与影响，不改包外文件或放宽测试。
