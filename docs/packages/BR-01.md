**要有推送权限才能做**：要推 `main`、推标签、删远端分支。没有推送权限就只做第 1 步检查，把结果写进「交付」后停下，交给 Claude 做。

## 目标
1. 把 `claude/inspiring-ride-zfnn4s`（含 DLV-03）合进 `main`，给 `main` 打标签 `v0.3`。
2. 删掉 GitHub 上已经合进来的旧分支。
3. 把文档里写死的旧分支名改成新规则：以后每件事从 `main` 开短分支，做完合回 `main` 再删。

## 步骤

### 1 检查（不推送）
```bash
git fetch origin --prune
git checkout claude/inspiring-ride-zfnn4s && git pull
# 每个远端分支相对本分支都必须是 0 个未合并提交
for b in $(git branch -r | grep -v HEAD); do echo "$b $(git rev-list --count HEAD..$b)"; done
# main 必须是本分支的祖先（能快进）
git merge-base --is-ancestor origin/main HEAD && echo ok
```
- 任何分支不是 0，或者 `main` 不能快进：**停下**，把输出写进交付，不要删、不要强推。
- 跑一遍全部检查：
  - `node tools/content.mjs check`
  - `node tools/check-levels.mjs`
  - `node tools/check-rooms.mjs`
  - `node tools/check-rooms2.mjs`
  - `node tools/art.mjs build`（必须 0 bumped）
  - `node tools/art.mjs verify`
  - `node --test tests/*.test.mjs`
  - `node tests/workbench.e2e.cjs`

  有失败就停下。

### 2 合进 main 并打标签
- 能开 PR 就开 PR：`claude/inspiring-ride-zfnn4s` → `main`，标题「v0.3：关卡线 30 关、界面定稿、配送 v2」。用**普通合并**（不要 squash、不要 rebase）。
- 不能开 PR 就快进推送：`git push origin claude/inspiring-ride-zfnn4s:main`（第 1 步已确认能快进；**不要 `--force`**）。
- 打标签：
  ```bash
  git fetch origin && git tag -a v0.3 origin/main -m "v0.3"
  git push origin v0.3
  ```

### 3 删旧分支（只删远端，删前再确认一次是 0）
- 要删的分支：
  - `codex/portitor-stage1`
  - `ui/style-proposals`
  - `claude/delivery-redesign`
  - `claude/lv-01-model`
  - `claude/ui-01-research`
  - `codex/art-ui-polish`
  - `chore/push-access-test`
  - `claude/inspiring-ride-zfnn4s`
- 命令：`git push origin --delete <分支>`。
- `main` 和标签 `v0.3` 不删。删之前对每个分支再跑一次 `git rev-list --count origin/main..origin/<分支>`，必须是 0。

### 4 改文档里的分支规则（在新分支 `docs/branch-rules` 上改，合回 `main`）

- 还没做的包里写死的旧分支名，改成「从 `main` 开 `<前缀>/<包号>`」：UI-06、UI-07、UI-08、UI-09、DLV-01、DLV-02。已完成的包是历史记录，不改。

## 不能碰的文件

## 验收标准
- `git ls-remote --heads origin` 只剩 `main`（如果第 4 步的 PR 还没合，还有 `docs/branch-rules`）。
- `git ls-remote --tags origin` 有 `v0.3`，指向合并后的 `main`。
- `main` 上第 1 步的检查全部通过。
- 交付里贴：第 1 步每个分支的未合并提交数、合并方式（PR 链接或快进）、删掉的分支清单、第 4 步改了哪些文件。
