# LV-01 设计模型：机关插件接口 + 关卡检查增强

状态：已派出（基线 `codex/portitor-stage1`，成果推到 `claude/lv-01-model`）
设计依据：[关卡质量标准](../design/level-quality.md)；[game-design.md](../design/game-design.md) 第 4 节（格子规则）、6.6；`content/catalog/mechanisms.json` 的 `spec_contract`

## 目标
让设计模型（`workbench/js/core/tilemodel.js`，工作台和 `tools/check-levels.mjs` 共用）能**按机关挂插件**，后面 LV-02–04 各自给第 3、4、5 章的机关写插件、互不冲突；同时让关卡检查直接给出关卡质量标准第 2 节要看的数字。

## 要做的事
1. 插件接口：一个机关一个文件（例如 `workbench/js/core/mech/<机关编号>.js`），向 tilemodel 注册：解析哪些地图字符 / 设备字段、每步结算时做什么、哪些格算支撑或阻挡、怎么参与状态键（搜索去重）。tilemodel 本身只加接口，不改第 1、2 章已有规则的结果。
2. `tools/check-levels.mjs` 每关输出：作者解是否通关、作者解步数、模型最短解步数、"捷径"标记（最短解比作者解短 2 步以上）、死局状态数、搜索是否触顶、有没有用到模型不认识的机关（列出来）。写进 `content/model-check.generated.json`，工作台「模式与关卡」页能看到这些数字。
3. 写一个示例插件证明接口能用：选一个最简单的游戏层机关（建议 `lantern_reveal` 灯照显形或 `nested_box` 套娃箱，按 `mechanisms.json` 的 `spec_contract` 和 game-design.md 的描述），并让对应的 Q08 / Q09 在模型里得到可信结果。
4. 测试：`tests/` 下加插件接口的单元测试（用临时数据）。
