# 界面美术调研（UI-01）

日期：2026-10-16　作者：制作方（UI-01）　性质：调研报告，不含候选美术。
依据：`art/export/reference/` 下 15 个界面（中英文）与 `level.*.png`、`art/export/preview/ui.*`、`art-direction.md` 第 2/3/7 节。
说明：本环境未联网核实，**参考作品全部凭已有知识写，链接为各作品的 Steam / 官网 / 常见资料页写法，未逐一打开核实**；"值得学"的描述是对其界面的概括，不是逐像素考据。`origin/codex/portitor-stage1` 中没有界面截图，游戏内实际样子以 `art/export/reference/` 为准（它们是 320×180 原生分辨率）。

## 1 现状问题清单（按严重程度）

总体印象：每个界面单独看都"能用"，问题出在**没有统一的造型语言**：面板是一块纯色矩形，按钮没有按钮的形状，装饰靠零散图标，世界观（万界渡口）几乎没出现在 UI 里。

### P1 严重
1. **全局：面板 = 纯色矩形 + 1px 线**（`ui.panel` 三态只是蓝灰/深蓝/棕红三块色）。暂停、过关、规则卡、结算、选关全是同一块棕红或深蓝矩形，没有边框厚度、角饰、阴影、内衬，缺少"物件感"。与场景里精致的箱子、砖墙、人物差一个档次——场景 16px 精灵细节丰富，界面却是 1 级信息量。
2. **关卡模式 vs 配送模式不像一个游戏**：关卡 HUD（`level.*`）是顶部深色条 + 右上角 5 个小图标；配送 HUD（`delivery_hud`）是红心、金币、药水、钟表、物品栏散落在顶部，字体、间距、图标风格各自为政。配送的 `shop`/`settlement`/`reels` 用的又是第三种面板（棕红大块 + 蓝色小按钮）。三套界面缺共同的母题。
3. **主菜单（lobby）毫无"万界渡口"**：标题"渡界人"贴在砖墙上，菜单是左下一块小深蓝框，右侧大片空砖墙；标题与菜单之间没有视觉层级，副标题和"当前章节"字号、颜色近似；标题没有 logo 化处理，是文字 + 一个橙色小方块图标。这是第一屏，却最弱。
4. **按钮没有三态之外的"按下"和清晰的"不可用"**：`complete`、`settlement`、`hint` 里的"下一关 / 选关 / 再送一单 / 回大厅"是**深蓝小矩形 + 文字**，与背景对比弱（深蓝压在深蓝砖上），看不出是可点的；选中态只靠黄色字或细边，焦点指示（菜单里的小三角、列表里的黄边）每个界面不同。

### P2 较重
5. **暂停/过关面板压在场景上，对比不足**：`pause`、`delivery_pause` 背景被压暗到几乎全黑，面板为棕红，菜单项只是文字行，选中行是蓝条 + 黄字，棕红底上的白字对比度只是勉强；标题"暂停"小而贴上沿。
6. **选关（levels）信息拥挤且对齐松散**：左列表行高 16px，右侧说明栏里只有一个小色块示意图，空洞；列表行的编号（M01）、标题、状态图标（勾/箭头）没有列对齐线，右侧小箭头像"二级菜单"误导；底部按键栏贴边，文字很小。
7. **章节选择（chapters）卡片风格零碎**：三张卡片大小不一（中间放大），第 2 章/第 3 章卡片内是缩略场景，左右卡片暗淡，选中卡片边框只有 1px；"0/7"进度小得像噪点；说明文字区是整块蓝灰，文字满格贴边，无留白。
8. **设置（settings）= 表格**：整页深色 + 一列列文字行，滑块是一排小方块，开关是"关"字的小框；没有分组、没有图标，选中行的蓝条把右侧数值也一起覆盖，层次平。
9. **规则卡/对话（rulecard、dialogue）**：气泡边框 1px，尾巴细，说话人标签（"老矿工"）是单独的橙色小标签，与气泡颜色、描边不是一个体系；规则卡右下的"Esc / 知道了"双按钮大小不一，Esc 键帽与按钮不对齐。
10. **配送 HUD（delivery_hud）图标挤**：左上红心、药水、两个格子、一包、金币 35、"×2"、急救包、梯子、空格、时钟 1:23、右上色块，间距不均、无分组，没有底板托住，叠在砖墙上时辨识度差。
11. **今天送什么（reels）**：双滚轮是亮点，但大标题"今天送什么?"黄色 2 倍字号与副标签（"货物/收件人"）、右边招财猫立绘之间无对齐；底部信息栏文字多、行距紧；"×1.5"红心的关系不清楚。
12. **结算（settlement / fail）**：数据表（完好度/用时/喜欢/小费…）右对齐数值，蓝色标签 + 白色数字 + 黄色总计，色彩过杂；"送到了!"标题与右上的徽章位置漂浮；失败页棕红面板上粉红标题，与成功页只有颜色差，缺情绪（没有插画/表情的重量）。

### P3 一般
13. **字号体系不清**：全站只有 1 倍和 2 倍两档，多处 1 倍正文紧贴面板边缘（没有统一内边距，常见 3–4px，应至少 6–8px）。
14. **图标风格不统一**：`ui.icons`（撤销/重开/灯泡/暂停）是细线粗糙小图标，`ui.menu_icons`（箭头、旗、钻石、门）是填色小块，`ui.delivery_icons`（红心、金币、药水）是写实小物件，三种画法并存。
15. **中英文排版**：英文单词宽度不一，按钮宽度靠"最长文字+留白"，导致按钮高度/形状不稳定；底部按键栏英文下经常只剩键帽。
16. **与主题背景的关系**：所有界面颜色固定（蓝灰/棕红），无论背景主题（石牢、遗迹、洞窟、森林、天空、宇宙）都不变，在森林/天空主题上会很突兀；而 lobby 的 `lobby.<theme>.png` 实际只换了背景图。
17. **动效缺位**：设计规定"界面过渡按整数像素移动"，但现有界面几乎没有可描述的过渡/弹跳/光标动画（参考图是静帧，需 UI-05 补）。

## 3 三个方向

共同约束：320×180 逻辑画面；ENDESGA 32；Fusion Pixel 12px（正文）与 10px（极小标注，仅限数字/按键说明），可整数倍放大（2×=标题）；九宫格角 6px；面板不透明、不渐变（可用 Bayer 抖动做过渡）；界面不画文字贴图；每个方向要同时覆盖关卡 HUD 与配送 HUD。

### 方向 A「渡口木牌」——木与纸的旧渡口
- **气质**：渡口小屋的木牌、账本、船票，温暖、手作、略旧。
- **世界观**：渡口里的送货铺：菜单像挂在码头的木牌，结算像盖章的收据，货物单像船票。直接呼应"渡界人 / 送货"。
- **颜色**：背景/描边 `#181425`、`#3e2731`、`#733e39`；木板 `#b86f50`、`#e4a672`、`#d77643`；纸 `#ead4aa`、`#c28569`；强调 `#feae34`/`#fee761`（选中、金币）；红印章 `#e43b44`/`#a22633`；暗面 `#262b44`。约 12 色。
- **面板与边框**：外 1px `#181425` 描边 + 2px 木框（上左亮 `#e4a672`、下右暗 `#733e39`），内衬 `#ead4aa` 纸面或 `#733e39` 深木；四角各一颗铆钉/钉子；标题用窄木条挂在顶边，两端有麻绳。母题：**钉子、纸角、绳结**。
- **按钮三态**：普通 = 木牌（`#b86f50` 底 + 亮上边）；选中 = 提亮到 `#e4a672` + 文字黄 + 左右两个小箭头/纸角卷起 1px + 上移 1px；不可用 = 灰褐 `#733e39` 底 + `#8b9bb4` 文字 + 删除线；按下 = 下移 1px、亮边变暗。
- **字号**：标题 12px×2（深棕字 + 1px 浅色下影），正文 12px（深色字用在纸面，白/米色字用在木面），数字与按键说明 10px；行距 14px。
- **图标**：16×16，深棕描边 + 填色，像烙在木牌上的符号；按键帽是小木块。
- **动效**：选中项上移 1px；面板进入从下方 4 帧整数像素滑入；盖章时 2 帧下压 + 1 帧抖动；翻页/滚轮保持现有。
- **优点**：与场景（箱子是木头）同族，复用现有棕色；关卡 / 配送 HUD 都容易统一。
- **风险**：木色与场景木箱/夯土相近，面板可能和游戏内物体混淆；棕色整体偏闷；英文多行的纸面排版需要仔细留白。
- **成本**：中。九宫格 + 少量角饰 + 重画 ~20 个图标；HUD 为木条。

### 方向 B「清爽现代像素」——扁平、高对比、信息优先
- **气质**：冷静、利落，像现代独立像素游戏（Celeste / Into the Breach 一路）。
- **世界观**：渡口是"调度中心"：界面像渡口的告示屏与票据，主题色淡淡地换，不抢场景。
- **颜色**：`#181425`、`#262b44`、`#3a4466`（面板）；`#5a6988`、`#8b9bb4`、`#c0cbdc`（描边与次要）；`#ffffff`（正文）；强调只用一个 `#fee761`（选中）+ 状态色 `#63c74d`（完成）、`#e43b44`（危险）、`#2ce8f5`（提示/配送）。约 12 色。
- **面板与边框**：2px 实边（上左 `#5a6988`、下右 `#181425`），内面板 `#262b44` 平色；**右下切角**（斜 3px）作为母题；标题栏是同色深一级的色条，左侧 4px 强调色块。无装饰，靠留白与对齐。
- **按钮三态**：普通 = `#3a4466` 平色 + `#8b9bb4` 文字；选中 = 反色（`#fee761` 底 + `#181425` 字）+ 左侧 2px 光标条；不可用 = 描边虚线 + `#5a6988` 文字；按下 = 底色变 `#c0cbdc`。
- **字号**：标题 12px×2 白字；正文 12px；数字、按键说明、HUD 注释 10px；颜色只用 3 档（白/灰/强调）。
- **图标**：16×16 单色线条为主（2px 线、圆角 1px），选中时填强调色；统一轮廓，像系统图标。
- **动效**：按整数像素的"条形扫过"选中；面板淡入用 Bayer 抖动 4 帧；数字滚动；光标条 2 帧闪。
- **优点**：最易读、最易中英文扩展、成本最低；HUD 统一最容易；不抢场景。
- **风险**：最无世界观，辨识度弱，容易"像任意一款游戏"；与场景的暖色细节反差大，可能显得"贴上去的"。
- **成本**：低。九宫格 + 一套线条图标。

### 方向 C「灯笼符箓」——强主题色的渡口之夜
- **气质**：夜里的渡口，灯笼、符纸、印章；神秘、有仪式感；每章可换灯色。
- **世界观**：渡口 = 通往万界的夜市码头；渡门 = 符箓门框；每个世界有一盏灯色。贴合"渡界人/地狱模式冥河"的气质，也方便融合东方元素。
- **颜色**：深夜底 `#181425`、`#262b44`、`#68386c`（紫）；符纸 `#ead4aa`、`#c0cbdc`；灯光 `#feae34`、`#f77622`、`#fee761`；朱红 `#e43b44`、`#a22633`；点缀 `#b55088`、`#2ce8f5`。每章（世界）替换灯色：石牢橙、遗迹金、洞窟青、森林绿 `#63c74d`、天空蓝 `#0099db`、宇宙紫 `#b55088`。约 14 色。
- **面板与边框**：深紫底 `#262b44`，边框是 1px 描边 + 2px 灯色线（主题色），**顶部和底部带符纸卷边/灯笼挂穗**；四角用门环/云纹；标题为一张竖挂的符纸（红印章标记）。母题：**灯笼、符纸、印章、云纹**。
- **按钮三态**：普通 = 深色底 + 灯色细边；选中 = 灯笼点亮（边框主题色 + 内发光抖动，文字 `#fee761`，左侧出现小灯笼）；不可用 = 蒙灰 + 印章被划掉；按下 = 灯色填满 1 帧。
- **字号**：标题 12px×2（朱红或灯色）；正文 12px 米色；数字 10px；标题可加朱红印章底。
- **图标**：16×16 剪纸/符号感，亮色填充 + 深色描边，像贴在灯笼上的剪纸；重点图标（金币、心）变成灯笼/印章形。
- **动效**：灯笼轻微摆动（4fps）；选中时灯光闪烁；换界面时符纸卷开 4 帧；结算盖章动画；与"环境层 4fps"节奏一致。
- **优点**：最有辨识度、最贴题材，可做主题色联动，结算/商店/滚轮很出彩。
- **风险**：最容易画重，视觉噪点多；与关卡模式（简洁推箱）可能过戏；东方符号需避免刻板或错用（要和多元世界观相容）；每章换灯色会增加验收项；紫色与 ENDESGA 的紫只有两格（`#68386c`、`#b55088`），层次有限。
- **成本**：高。装饰多、每章换色、动画帧多。

## 4 样稿界面建议

固定 4 张（三个方向共用）：
1. **lobby 大厅**——第一印象，最能体现世界观与标题 logo；考验装饰、主题背景融合、层级。
2. **levels 关卡选择**——密度最高的列表 + 说明栏，考验对齐、选中态、图标统一、章节主题色。
3. **pause 暂停**——覆盖在场景之上的模态面板，考验对比度、按钮三态；也可直接推广到 `delivery_pause`、`hint`、`rulecard`。
4. **settlement 送达结算**——配送模式的最复杂面板（数据表、徽章、按钮、情绪），也是配送与关卡"像不像一个游戏"的对照点。

理由：这四张覆盖菜单、列表、模态、数据表四类布局；若画得好，其他界面（chapters、settings、hint、rulecard、shop、reels 等）可由它们的组件推导。
可考虑用 **delivery_hud**（含关卡 HUD 对照）替换 `pause`：如果用户最在意"游戏内一直看到的东西"，HUD 比暂停更重要。建议 UI-02 在比较台里每个方向额外附一条 HUD 横幅（关卡 + 配送各一）作为第 5 项小样，不增加整屏工作量。

## 5 建议

- 样稿用同一份 UI 组件表：面板 3 种尺寸、按钮三态、列表行、键帽、图标 8 个（撤销/重开/提示/暂停/继续/设置/金币/红心），以便用户并排比较。
- 样稿都放 320×180 原生，并附 3× 放大图；中英文各出一套。
- 无论选哪个方向，先统一：内边距 ≥6px、图标一套画法、焦点指示一种、关卡与配送共用 HUD 底板。
- 我的倾向（仅供用户参考）：B 作为"基底骨架"（低成本）+ A 的木质/纸面作为配送与结算的点缀，或 C 作为"最有记忆点"的选项；最终由用户选。
