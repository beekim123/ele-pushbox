原设计中若干几何说明无法直接按现有规则回放，因此做了以下校准，供用户验收：

- **T01**：原平台支撑与“落坑后继续向右推”的八步路线冲突。将高台及箱子上移一格，保持人物 `[1,4]`、目标 `[8,4]` 和 10×6，解法为 `R U U R R R R R`（R 为右移，U 为上爬），八步完成；另单独验证 D 向下爬梯。
- **T02**：保留左侧竖向两格沙源。自然坍塌后初次相邻挖掘只获得 136 cells，增加向左走近、再挖一次及返回高台旁的引导；最终倾倒一袋 256 cells 造坡。
- **T03**：从左臂井口上方的空格倾倒，避免向已含水的格子只倒出部分沙。两侧梯子保障人物过井及推箱后不落井。拉杆后箱从 `[6,5]` 浮至 `[6,4]`，倒一袋沙后浮至 `[6,3]`；254 cells 落入 `[4,6]` 沉沙囊，水平管保持连续 WATER 类别。

没有修改 `board.gd`、`session.gd`、`rules.json`、D1–D5、SDK 或其材料/反应配置。纯代码生成器采用 ENDESGA 32 字符像素矩阵和绘制函数；原 PNG 留作参考，运行和测试均不依赖它们。

## 审核修正与失败留痕

只读代码审核发现的 P2 已关闭：检查临时进度文件写入及 flush 后错误状态，成功才替换旧档，失败保留待保存标志，同关完成或返回大厅可以重试。大厅专项已覆盖故障注入和旧档保留。

后续引导必须等待 `after` 条件完成，避免因开局站位提前消失。悬停预演现在在指针当帧启动并执行既有 3.5 ms 首个工作切片，减少等待；求解器、步骤和哈希保持相同。

测试中真实鼠标事件曾覆盖脚本坐标，隔离项目设置窗口输入标志，T8 直接控制指针时关闭 Game 原生 `_input`；脚本注入输入测试保持可用，正式游戏输入不变。窗口标志依据 [Godot Window API](https://docs.godotengine.org/en/stable/classes/class_window.html)。

过程中曾出现高负载帧超限、旧调度预演超限及一次渲染等待超时，未判为通过。观察到聊天渲染进程约 383% CPU 时暂停新增计算，负载下降后顺序复核。失败证据保留于 [完整轮 T8 失败日志](logs/full-suite-t8-failure.log)、[失败性能数据](logs/full-suite-t8-failure.json)、[输入事件追踪](logs/lobby-performance-trace.log) 和 [教学时序复核](logs/tutorial-timing-trace.log)。最终通过证据单独保存在 `logs/final/`，没有放宽性能阈值。

SDK 清理证据及将来仅安装编译产物的建议见 [SDK 运行产物核对](sdk-runtime-review.md)；本次没有开展 SDK 扩展或第二阶段。
