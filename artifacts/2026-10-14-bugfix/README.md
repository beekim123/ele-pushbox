# Bug 修复验证记录

日期：2026-10-14（Asia/Shanghai）。用户要求恢复 Bug 排查，并选择“保持像素清晰，画面和界面随窗口宽高适配”。验证环境为 Godot 4.7.2、macOS/OpenGL、Apple M3。所有计算顺序执行，单 worker，数值库线程为 1；使用隔离项目和 user 目录。

## 已确认并修复的问题

| 问题 | 根因与修复 | 验证 |
|---|---|---|
| 屏幕宽高适配 | 固定 320×180 画布留下大面积边框，界面和点击坐标也固定。现在按窗口计算整数像素画布，居中关卡和 SDK 画面，背包靠右、菜单居中，输入转换到实际关卡坐标。 | 横屏、4:3、超宽、非整除尺寸、竖屏、恢复 16:9；地形像素对照、点击、炸药拖放、撤销、全屏闪光。 |
| 原生拖动缩放后仍出现黑边 | 在 `size_changed` 信号内直接修改画布尺寸造成重入，外层窗口更新覆盖新的显示区域。现在合并通知并延迟到信号结束后布局。 | 信号深度回归先失败后通过；真实拖动窗口至 1202×546 后确认边框消失，仅保留整数缩放不可整除的余量像素。 |
| 上台阶时人物看起来穿过障碍 | 原动画沿对角线插值，人物矩形在途中切过实体拐角。现在先上移，再横移。 | 5 个途中位置无障碍交叠，落点不变；D1 两格高墙仍阻止普通行走。 |
| 人物朝左时偏移一整格 | 翻转绘制矩形时额外加了 16 像素。现在在原位置镜像精灵。 | 挖左后模型位置不变，每个不透明人物像素与原精灵的水平镜像逐像素一致；原生点击挖取、倒出、撤销时人物留在原格。 |

仍保留原规则允许的单格登台阶；本轮没有发现或修改离散规则中的非法越障。用户若仍遇到其他越障现象，需要按具体关卡、位置和输入另行复现。

关卡仍按 320×180 的基础布局绘制，窗口多出的面积用于自适应背景与界面布局。整数倍率至少为 1，最小窗口为 320×180；每个方向剩余边框少于一个放大后的逻辑像素。SDK 世界仍为 320×192，模拟与房间裁剪保持原样。屏幕适配依据 [Godot 多分辨率文档](https://docs.godotengine.org/en/stable/tutorials/rendering/multiple_resolutions.html)；重入机制结合实际失败与 [Godot Window 更新源码](https://github.com/godotengine/godot/blob/master/scene/main/window.cpp) 定位。

## 复现与证据沿革

专项测试可用 `python3 tools/run_tests.py --only bugfix`；全套可用 `python3 tools/run_tests.py --performance`。运行前核对全机计算预算。测试产生的默认输出位于 `artifacts/v03/logs/`，本轮实际从独立副本运行，再归档到本目录，原仓库历史 v0.3 证据未覆盖。

- `red/`：未修复时 19 项中 13 项失败，覆盖台阶动画、尺寸和输入。
- `resize-red/`：仅切换 expand 后，非整除尺寸与竖屏仍有 4 项失败。
- `reentrant-red/`：直接在尺寸信号中布局时，38 项中 5 项失败。
- `mirror-red/`：有效的逐像素镜像测试，40 项中 1 项失败；没有采用会混入沙色而误通过的旧检测方式。
- `suite-first/`：初次全套只执行到 8/14，输入测试失败。已确认是测试仍使用旧固定坐标；测试目标改为实际绘制位置，原 SDK 数量与 hash 断言保留，最终 14/14 通过。
- `green/` 和 `logs/`：最终修复后的专项与全套结果。
- `manual.log` 是首次试玩，`manual-final.log` 是窗口适配阶段试玩，均保留当时现象；最终朝向修复验证为 `manual-mirror-final.log` 的重开后最后四个状态和 `manual-captures/`。
